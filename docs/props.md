# Справочник пропов

Все пропы `AnchorList`. Тип — `IAnchorListProps<TItem>`, где `TItem` выводится из
`data`.

Обязательны только четыре: данные, отрисовка строки, ключ и стартовая оценка
размера. Всё остальное включает отдельные механики.

## Данные и отрисовка

### `data: readonly TItem[]`

**Обязательный.** Массив элементов. Список не копирует и не мутирует его.

Сравнивается по ссылке: новый массив запускает разбор данных — пересчёт ключей,
типов и объявленных размеров. Мутация существующего массива на месте
(`data.push(...)`) списком не замечается.

### `renderItem: (props: IAnchorListRenderItemProps<TItem>) => ReactNode`

**Обязательный.** Отрисовка одной строки.

```ts
interface IAnchorListRenderItemProps<TItem> {
  item: TItem;
  index: number;
  itemKey: string;
  type: string;
  extraData: unknown;
  stickyOffset?: SharedValue<number>;
  stickyPinned?: SharedValue<boolean>;
}
```

| Поле | Что это |
| --- | --- |
| `item` | Сам элемент |
| `index` | Индекс в **текущих** данных: после подгрузки сверху он у элемента другой |
| `itemKey` | Ключ из `keyExtractor`. Им адресуют состояние строки во внешнем сторе — в отличие от `index`, он у элемента не меняется |
| `type` | Значение, вернувшееся из `getItemType`; пустая строка, если проп не задан |
| `extraData` | Значение пропа `extraData` |
| `stickyOffset` | Смещение прилипания для якорей в режиме `offset`; у остальных строк — `0`. Живёт на UI-потоке, применять через `useAnimatedStyle` |
| `stickyPinned` | Прилипшую копию рисует слой поверх списка: узел, к которому применяется `stickyOffset`, нужно спрятать, оставив на месте для касаний |

Функцию нужно мемоизировать: она уходит в каждый смонтированный контейнер.

Подробности — [Отрисовка строк](rendering.md), последние два поля —
[Прилипание](sticky.md#режим-offset).

### `keyExtractor: (item: TItem, index: number) => string`

**Обязательный.** Постоянный ключ элемента. От индекса зависеть не должен.

По ключу список узнаёт элемент после подгрузки и вставки; на нём держатся
измеренные размеры, переработка контейнеров и удержание видимой позиции.
Дубликаты не допускаются.

### `extraData?: unknown`

Значение, доходящее до каждой ячейки полем `extraData` в `renderItem`: им
перерисовывают строки извне, не трогая `data`.

## Размеры и переработка

### `estimatedItemSize: number`

**Обязательный.** Стартовая оценка высоты строки до первого измерения.

Влияет на качество первых кадров. После первых замеров неизмеренные строки
оцениваются по среднему для их типа, а не по этому числу.

### `getItemType?: (item: TItem, index: number) => string`

Тип контейнера для переиспользования. Контейнер того же типа уже держит нужное
поддерево, поэтому React меняет пропы вместо перемонтирования.

Работает вместе с `recycleItems`. Строки заметно разной формы должны получать
разные типы.

```tsx
getItemType={row => (row.type === "message" && row.hasImage ? "media" : row.type)}
```

Тип также задаёт отдельный счётчик среднего размера: строки одного типа
оцениваются по своим замерам, а не по общим.

### `getFixedItemSize?: (item, index, type) => number | undefined`

Известный размер элемента — измерение для него пропускается.

Возврат `undefined` означает «размер неизвестен, измеряй». Это позволяет задать
точные размеры части строк (разделители, спиннеры) и оставить измерение остальным.

```tsx
getFixedItemSize={row => {
  if (row.type === "day") return 44;
  if (row.type === "spinner") return 56;

  return undefined; // сообщения измеряются
}}
```

Объявленный размер живёт в метриках и обратно в оценочный не превращается: если
нужно перевести список с объявленных размеров на измеряемые, его придётся
пересоздать (сменой `key`).

### `recycleItems?: boolean`

По умолчанию `false`. Переиспользовать смонтированные контейнеры вместо
перемонтирования.

С включённой переработкой контейнер переживает смену элемента: меняются его
пропы, поддерево остаётся.

> [!WARNING]
> **`useState` внутри строки при этом достаётся чужому элементу:** он живёт
> вместе с контейнером. Для состояния, живущего пока строка на экране, есть
> [`useAnchorListItemState`](rendering.md#состояние-внутри-ячейки); состояние,
> обязанное пережить уход строки за пределы диапазона, держат во внешнем сторе
> по `itemKey`.

### `itemsAreEqual?: (prev: TItem, next: TItem, index: number) => boolean`

Сравнение элементов для пропуска повторного рендера ячейки. По умолчанию
элементы сравниваются по ссылке: новый объект с теми же полями перерисует строку.

```tsx
itemsAreEqual={(prev, next) => prev.id === next.id && prev.text === next.text}
```

### `drawDistance?: number`

По умолчанию `400`. Запас отрисовки за пределами вьюпорта, px.

Строки этого запаса смонтированы и измерены заранее, к моменту, когда до них
доходит скролл. По ходу движения запас дополнительно растёт со скоростью — этим
список распоряжается сам, и настраивать это нельзя.

См. [Производительность](performance.md#drawdistance).

### `scrollThrottleDistance?: number`

По умолчанию `24`. Через сколько пикселей прокрутки список пересчитывает, какие
строки должны быть на экране.

Величина в **пикселях**, не в миллисекундах: порог по пути, а не по времени.

**Значения в `state` обновляются такими же шагами.** У кромок контента шаг не
применяется при любом значении.

На `sharedValues` это не влияет: смещение, фазы жеста, расстояния до кромок и
флаги считаются на UI-потоке каждым кадром.

## Слоты

### `ListHeaderComponent?: ComponentType<unknown> | ReactElement | null`

Шапка списка. Принимается и элементом, и типом компонента.

Высота шапки измеряется и входит в полную высоту контента, но не в `totalSize`
(суммарную высоту элементов). Смещения элементов внутри списка считаются в
координатах элементов, а наружу отдаются в координатах контента — с учётом шапки.

### `ListFooterComponent?: ComponentType<unknown> | ReactElement | null`

Подвал списка. Сюда обычно ставят распорку под панель ввода —
см. [Отступы и клавиатура](insets.md).

### `ListEmptyComponent?: ComponentType<unknown> | ReactElement | null`

Показывается вместо элементов, когда `data` пуст. Шапка и подвал при этом
остаются на месте.

### `ItemSeparatorComponent?: ComponentType<unknown> | null`

Рисуется внутри ячейки, под содержимым строки, и **входит в её высоту**.

Это отличается от `FlatList`, где разделитель — отдельный узел между ячейками.
Здесь он часть ячейки, поэтому измеренная высота строки включает разделитель, и
`getFixedItemSize` для такой строки тоже обязан его учитывать.

## Раскладка и позиция

### `alignItemsAtEnd?: boolean`

По умолчанию `false`. Прижать контент к концу, когда он короче вьюпорта.

Разницу добирает сдвиг слоя контейнеров вниз: высота контента от него не
меняется, короткий список остаётся непрокручиваемым.

Место под панелью ввода из сдвига вычитается — его отдаёт распорка
[`insetEnd`](#insetend-sharedvaluenumber). Пока контента меньше экрана, этот же
сдвиг поднимает его вместе с клавиатурой.

### `initialScroll?: AnchorListInitialScroll`

Позиция, с которой список открывается.

```ts
type AnchorListInitialScroll =
  | { type: "end" }
  | { type: "offset"; offset: number }
  | {
      type: "index";
      index: number;
      viewPosition?: number;
      viewOffset?: number;
    };
```

До применения стартовой позиции список не показан.

Пока стартовый скролл активен, пороги кромок не проверяются.

Подробности — [Скролл и позиционирование](scrolling.md#стартовая-позиция).

### `maintainVisibleContentPosition?: IAnchorListMaintainVisibleContentPosition<TItem>`

Удержание видимой позиции при изменениях выше вьюпорта.

```ts
interface IAnchorListMaintainVisibleContentPosition<TItem> {
  data?: boolean;
  size?: boolean;
  shouldRestorePosition?: (item: TItem, index: number) => boolean;
}
```

| Поле | По умолчанию | Что делает |
| --- | --- | --- |
| `data` | `false` | Компенсировать вставку и удаление элементов |
| `size` | `false` | Компенсировать изменение размеров уже отрисованных элементов. На быстром броске не работает — [почему](maintain-position.md#компенсация-размеров-не-работает-на-броске) |
| `shouldRestorePosition` | — | Выбор якоря восстановления; по умолчанию — первый видимый элемент |

Полный разбор — [Удержание позиции](maintain-position.md).

### `maintainScrollAtEnd?: IAnchorListMaintainScrollAtEnd`

Автоприлипание к концу списка при добавлении элементов.

```ts
interface IAnchorListMaintainScrollAtEnd {
  onlyWhenAtEnd?: boolean;
  animated?: boolean;
}
```

| Поле | По умолчанию | Что делает |
| --- | --- | --- |
| `onlyWhenAtEnd` | `false` | Прилипать только если пользователь уже у конца |
| `animated` | `false` | Доводить позицию анимацией, а не мгновенно |

Сам факт наличия объекта включает механику; `undefined` её выключает.

### `maintainScrollAtEndThreshold?: number`

По умолчанию `0.1`. Порог «у конца» в долях длины вьюпорта — для
`maintainScrollAtEnd` и сигнала `isWithinMaintainScrollAtEndThreshold`.

Это **отдельный** порог от порогов подгрузки: «у низа» для кнопки возврата и
«пора подгружать» — разные расстояния.

### `anchoredEndSpace?: IAnchorListAnchoredEndSpace`

Распорка у конца списка, растущая до якоря.

```ts
interface IAnchorListAnchoredEndSpace {
  anchorIndex: number;
  anchorOffset?: number;
  maxSize?: number;
  onSizeChanged?: (size: number) => void;
}
```

| Поле | Что делает |
| --- | --- |
| `anchorIndex` | Элемент, который должен доставать до верхней кромки |
| `anchorOffset` | Дополнительный отступ над якорем |
| `maxSize` | Верхняя граница размера распорки |
| `onSizeChanged` | Текущий размер распорки; меняется вместе с раскладкой |

Резервирует место под последним элементом ровно настолько, чтобы якорный
элемент мог подняться к верхней кромке вьюпорта: так работает переход к
цитируемому сообщению у самого конца переписки.

В отступ конца распорка входит, в расстояние до кромки для порогов подгрузки —
нет.

### `snapToIndices?: number[]`

Точки притяжения скролла. Индексы переводятся в смещения и уходят в
`snapToOffsets` нативного `ScrollView`.

Смещения считаются на рендере, поэтому до измерения соответствующих строк они
приблизительны.

## Прилипание

### `sticky?: IAnchorListStickyConfig<TItem>[]`

Наборы прилипающих элементов. На каждой кромке — не более одного набора.

```ts
interface IAnchorListStickyConfig<TItem = unknown> {
  edge: "start" | "end";
  indices: number[];
  offset?: SharedValue<number>;
  mode?: "container" | "offset";
  size?: number;
  groupStarts?: number[];
  limitInset?: number;
  renderOverlay?: (item: TItem, index: number) => ReactNode;
}
```

| Поле | По умолчанию | Что делает |
| --- | --- | --- |
| `edge` | — | Кромка, у которой останавливаются якоря набора |
| `indices` | — | Индексы якорей, **по возрастанию** |
| `offset` | высота распорки `insetEnd` у конечной кромки, `0` у начальной | Отступ от кромки: навбар сверху, панель ввода, клавиатура и безопасная зона снизу. Shared value, потому что величина динамическая. Снизу подставляется [`insetEnd`](#insetend-sharedvaluenumber), если не задан свой |
| `mode` | `"container"` | `container` — прилипает вся строка; `offset` — строка стоит на месте, смещение приходит в `renderItem` |
| `size` | высота строки | Высота прилипающего объекта в режиме `offset` |
| `groupStarts` | — | Индекс первой строки группы для каждого якоря, параллельно `indices` |
| `limitInset` | `0` | Сдвиг верхней границы группы вниз, px |
| `renderOverlay` | `renderItem` в режиме `container` | Прилипшая копия якоря для слоя поверх списка |

Индексы адресуют строки в **текущих** данных: если сверху появился спиннер, все
индексы сдвинулись на единицу, и их нужно пересчитать.

Полный разбор обоих режимов — [Прилипание](sticky.md).

## Пороги кромок

### `onStartReached?: (info: { distanceFromStart: number }) => void`

Скролл подошёл к началу контента — пора подгружать предыдущую страницу.

Вызывается **один раз на жест**: пока пользователь не оторвал палец и не
двинулся в другую сторону, повторно порог не срабатывает.

### `onStartReachedThreshold?: number`

По умолчанию `0.5`. Порог начала в долях длины вьюпорта. `0.5` — половина экрана
до кромки.

### `onEndReached?: (info: { distanceFromEnd: number }) => void`

Скролл подошёл к концу контента. Та же однократность, что у `onStartReached`.

`distanceFromEnd` считается **без** отступа конца (`anchoredEndSpace` и распорка
`alignItemsAtEnd` в него не входят).

### `onEndReachedThreshold?: number`

По умолчанию `0.5`. Порог конца в долях длины вьюпорта.

Подробнее о поведении порогов — [Подгрузка](pagination.md).

## Состояние наружу

### `sharedValues?: IAnchorListSharedValues`

Shared values, которые список публикует для worklet-логики. Заполняются только
те поля, которые переданы, — остальные не стоят ничего.

25 значений: смещение и скорость скролла, фаза жеста, размеры контента и
вьюпорта, флаги и расстояния до кромок, видимый диапазон, активные якоря
прилипания.

Полный перечень — [Состояние списка](state.md#sharedvalues).

### `state?: AnchorListState`

Состояние списка для JS: подписка с перерисовкой.

Создаётся через `useAnchorListState()` **вне** списка и читается через
`useAnchorListValue(state, name)`, в том числе из соседних компонентов.

Подписаться можно до монтирования списка: до этого значения `undefined`, дальше
подписки перевешиваются на стор списка.

Для анимаций — `sharedValues`.

### `viewabilityPairs?: IAnchorListViewabilityPair<TItem>[]`

Пороги видимости и их обработчики. Наборов может быть несколько: аналитике и
автовоспроизведению нужны разные пороги на одном и том же списке.

См. [Видимость элементов](viewability.md).

### `insetEnd?: SharedValue<number>`

Сколько низа вьюпорта занято не списком: панель ввода, клавиатура, безопасная
зона. От этого значения список сам:

- **ставит распорку в конце контента** — последняя строка останавливается над
  панелью, `scrollToEnd` и автоприлипание считаются без поправок;
- **вычитает отступ из выравнивания**
  ([`alignItemsAtEnd`](#alignitemsatend-boolean));
- **поднимает смещение** вместе с отступом, когда контент длиннее экрана;
- **отодвигает индикатор скролла**;
- **отодвигает якорь конечной кромки**. Набор прилипания может задать свой
  `offset` — он приоритетнее.

Тип — shared value: всё перечисленное считается на UI-потоке и едет с
клавиатурой в один кадр.

Safe area уже входит в значение, поэтому авто-подстройка инсетов индикатора
(`automaticallyAdjustsScrollIndicatorInsets`) отключается.

Полностью — [Отступы и клавиатура](insets.md).

## События

| Проп | Когда вызывается |
| --- | --- |
| `onLoad?: () => void` | Первая раскладка завершена, стартовый скролл применён |
| `onLayout?: (event: LayoutChangeEvent) => void` | Размер вьюпорта изменился |
| `onContentSizeChange?: (width: number, height: number) => void` | Размер контента изменился |
| `onScrollBeginDrag?: () => void` | Палец лёг на экран: внешняя логика позиции обязана уступить жесту |
| `onScrollEndDrag?: () => void` | Палец отпущен; дальше возможна инерция |

Отдельного `onScroll` нет: смещение отдаётся через `sharedValues.scrollOffset`
и живёт на UI-потоке.

## Стили и refs

### `style?: StyleProp<ViewStyle>`

Стиль **обёртки** списка: размеры и фон. Внутри обёртки, снаружи `ScrollView`,
живёт слой прилипших копий.

### `contentContainerStyle?: StyleProp<ViewStyle>`

Стиль контента внутри `ScrollView`: отступы вокруг элементов.

### `refScrollView?: AnimatedRef<Animated.ScrollView>`

Ref нижележащего `ScrollView`. Нужен тем, кто двигает позицию с UI-потока —
например компенсации клавиатуры. Если не передан, список заводит свой.

### `ref?: React.Ref<IAnchorListRef>`

Императивный интерфейс списка — см. [Императивный API](imperative-api.md).
