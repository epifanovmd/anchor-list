# Диагностика

Симптом → причина → что делать.

## Список пустой

| Проверить | Как |
| --- | --- |
| У списка есть высота | `style={{ flex: 1 }}` или явная высота. Обёртка не растягивается сама |
| `data` не пуст | И это **новый** массив, а не мутированный на месте |
| `estimatedItemSize` больше нуля | С нулём строкам не отводится места |
| Родитель не схлопнут | Обёртки с `flex: 1` до самого экрана |

Если `data` пуст намеренно — задайте `ListEmptyComponent`.

## Список мигает или дёргается при открытии

**Оценка размера сильно расходится с правдой.** Список открывается по
`estimatedItemSize`, потом переставляет всё по измерениям.

Что делать: уточнить `estimatedItemSize`, а лучше объявить размеры через
`getFixedItemSize` там, где они известны.

**Задан `initialScroll` на неизмеренные строки.** Цель уезжает после каждого
кадра измерений; список доводит её до 10 раз.

Что делать: задать `getFixedItemSize` хотя бы для строк до цели.

## Контент прыгает при подгрузке сверху

Не включена компенсация:

```tsx
maintainVisibleContentPosition={{ data: true, size: true }}
```

Если включена, а прыжок остался — смотрите строку `mvcp` в
[замере](performance.md#встроенный-замер):

| Что видно | Причина | Что делать |
| --- | --- | --- |
| `без якоря` растёт | Ключи нестабильны, якорь не находится после изменения | `keyExtractor` не должен меняться вместе с элементом |
| `упор` и `потеряно` | Сдвиг упёрся в границу скролла | Проверить, не короче ли контент вьюпорта |
| Записей нет вовсе | Объект `maintainVisibleContentPosition` пересоздаётся каждый рендер | Мемоизировать |

## Строки налезают друг на друга

**Объявленный размер не совпадает с фактическим.** `getFixedItemSize` — это
обещание: список отводит ровно столько и не проверяет.

Что делать: убедиться, что объявленная высота включает всё — отступы,
`ItemSeparatorComponent`, границы. Или вернуть `undefined` и дать измерить.

**Ячейка меняет высоту после измерения.** Например, разворачивается по тапу без
`maintainVisibleContentPosition.size`.

## Прилипающие заголовки липнут не там

**Индексы устарели.** `sticky[].indices` адресуют строки в текущих данных. Спиннер
сверху сдвигает всё под собой на единицу:

```tsx
const indices = useMemo(
  () => (loadingStart ? base.map(index => index + 1) : base),
  [base, loadingStart],
);
```

**Индексы не по возрастанию.** Требование, а не рекомендация.

**Наборов на одну кромку больше одного.** На каждой кромке — не более одного.

## Прилипающие заголовки не двигаются

Плагин worklets не применён к коду библиотеки: worklet не собрался, смещение
всегда `0`.

Что делать: см. [Установка → настройка babel](installation.md#настройка-babel).

## Прилипший аватар дрожит или прыгает

**Не задан `renderOverlay`.** В режиме `offset` он обязателен: у кромки стоит не
строка, а объект внутри неё.

**Копия встаёт не на то место.** Горизонтальные отступы `renderOverlay` обязаны
повторять слот объекта в строке.

**Аватар размонтируется вместо того, чтобы прятаться.** По `stickyPinned` нужно
менять `opacity`, а не убирать узел:

```tsx
opacity: stickyPinned?.value ? 0 : 1  // да
{!stickyPinned?.value && <Avatar />}  // нет
```

**Аватар уезжает выше своей группы.** Не заданы `groupStarts`, `size` или
`limitInset` — см. [Прилипание](sticky.md#режим-offset).

## Подгрузка вызывается слишком часто

Она вызывается один раз на жест, но жест может закончиться и начаться снова
раньше, чем придёт ответ. Свой флаг всё равно нужен:

```tsx
const handleStartReached = useCallback(() => {
  if (loading || !hasMore) return;
  // ...
}, [loading, hasMore]);
```

## Подгрузка не вызывается

| Проверить | Как |
| --- | --- |
| Порог не слишком мал | `onEndReachedThreshold` — доли вьюпорта; `0.5` = полэкрана |
| Не идёт программный скролл | Пока активны `initialScroll` или `maintainScrollAtEnd`, пороги молчат |
| Гейт не занят другой кромкой | На коротком контенте кромка отдаётся по направлению жеста |
| Расстояние считается как ожидается | `sharedValues.distanceFromEnd` — распорки конца в него не входят |

## Последняя строка уходит под панель ввода

Нет распорки в подвале. Место под панелью отдаётся списку контентом —
см. [Отступы и клавиатура](insets.md).

## Индикатор скролла доходит до низа экрана

Не передан `insetEnd`. Индикатор живёт в координатах `ScrollView` и о
распорке в подвале не знает.

На iOS, если индикатор наоборот кончается слишком высоко, — safe area посчитана
дважды: она уже входит в переданное значение.

## Строки «залипают» чужим содержимым

Ячейка хранит состояние внутри себя, а контейнер переработан под другой элемент.

Что делать: состояние должно приходить из `item` или из внешнего стора по ключу.
См. [Отрисовка строк](rendering.md#переработка-контейнеров). Как временная мера —
выключить `recycleItems`.

## В кадре видны пустые полосы

Диапазон не успевает за скроллом. В замере это раздел `пустоты`.

| Причина | Что делать |
| --- | --- |
| Тяжёлые строки | Профилировать `renderItem` |
| Мал буфер | Увеличить `drawDistance` до 600–800 |
| Данные пересобираются целиком | Задать `itemsAreEqual` |
| Оценка размера сильно занижена | Уточнить `estimatedItemSize` и `getItemType` |

## Список тормозит на быстром скролле

Смотрите замер целиком: [Производительность](performance.md#как-читать).

Чаще всего дело не в списке, а в содержимом строк: `длинных` кадров много, а
`диапазон` и `привязка` при этом дешёвые.

## Скролл к элементу попадает мимо

Позиция дальней строки оценочная, пока строка не измерена.

Что делать: задать `getFixedItemSize` хотя бы для строк до цели. Либо
использовать `viewPosition: 0` и доводить повторным вызовом после измерения.

## `useAnchorListValue` возвращает `undefined`

Список ещё не смонтирован. Это нормальное состояние — обрабатывайте его явно:

```tsx
const first = useAnchorListValue(state, "firstVisibleIndex") ?? -1;
```

Если `undefined` держится и после монтирования — проверьте, что **тот же** объект
`state` передан списку пропом.

## Компоненты перерисовываются на каждом кадре скролла

Значение читается через `state`, а не `sharedValues`. Смещение и скорость через
React гонять нельзя — см. [Состояние списка](state.md).

## `Tried to synchronously call a non-worklet function on the UI thread`

Плагин worklets не применён к коду библиотеки. См.
[Установка](installation.md#настройка-babel).

## Прилипание ведёт себя странно, а причина не видна

Расчёт прилипания идёт в трёх местах сразу: ядро выбирает активный якорь,
привязка публикует его геометрию контейнеру, worklet считает смещение на каждом
кадре. Расхождение любых двух видно на экране как исчезнувший или застывший
якорь, но по самому экрану не сказать, какое из трёх ошиблось.

```ts
import { setStickyDebug } from "@epifanovmd/anchor-list";

setStickyDebug(true);
```

В консоль пойдут только изменения — повтор той же строки отбрасывается:

| Раздел | Что показывает |
| --- | --- |
| `active` | Какой якорь ядро считает активным, его предел, скролл, вьюпорт |
| `bind` | Что получил контейнер: номер, кромка, позиция, размер, предел |
| `pin` | Что видит слой копий: активный индекс, рисует ли он его, геометрия |
| `frame` | Копия внутри контента: видима ли, её экранная координата |
| `overlay` | Копия в слое поверх списка: видима ли, её экранная координата |

Как читать: в момент передачи якоря `overlay ... скрыт` и `frame ... виден`
обязаны случиться на одном пикселе, и `экран` у обоих обязан совпасть. Разрыв
между ними — и есть дефект. Если же координаты сходятся, а на экране якоря нет,
дело не в расчёте, а в отрисовке: скорее всего его перекрывает соседняя строка.

Есть и объектная форма — `anchorListStickyDebug.enable()` / `.disable()`; она не
трогает UI-поток, поэтому worklet-строки (`frame`, `offset`) с ней не печатаются.
Для полной картины нужен `setStickyDebug`.

## Ничего из перечисленного

1. Включите замер: `useAnchorListPerf("debug")`.
2. Посмотрите, какой раздел отчёта выглядит ненормально —
   [как читать](performance.md#как-читать).
3. Сравните поведение с соответствующим стендом в [`example/`](../example): если
   там всё в порядке, разница где-то в конфигурации.
4. Соберите минимальный воспроизводимый пример и
   [заведите issue](https://github.com/epifanovmd/anchor-list/issues).
