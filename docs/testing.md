# Тесты

```sh
yarn test              # весь набор
yarn test --watch      # в режиме наблюдения
yarn test visible-range # по имени файла
yarn check             # линт + типы + тесты
```

**57 наборов, 637 тестов.**

## Как устроено

`testEnvironment: node`. RN-рантайм не поднимается: тестируется чистая логика
ядра, а worklet-директивы в Node — обычные функции.

Трансформ — babel с пресетом React Native **без** плагина Reanimated
(`babel-jest.config.js`). Директивы `"worklet"` остаются строками, и worklet-код
проверяется как обычные функции — что и требуется: он и написан так, чтобы быть
проверяемым.

Именно поэтому тесты идут за секунду, а не за минуту.

## Чего тесты не проверяют

**Отрисовку.** Тестов, рендерящих `AnchorList` целиком, нет: для этого нужен
RN-рантайм с работающим `ScrollView`, реальными `onLayout` и нативным
`maintainVisibleContentPosition`. Всё, что можно проверить без них, вынесено в
ядро — и проверяется.

**Нативное удержание позиции.** Сдвиг выполняет `ScrollView`. Тесты проверяют,
какую позицию распорки список ему выставит, но не то, что нативный слой сделает
дальше.

**Кадры и производительность.** Замер есть, автоматических порогов по нему — нет.

Эти три области проверяются стендами в [`example/`](../example): по одному на
механику, с тумблерами, отключающими проверяемое поведение.

## Добавление тестов

Тесты лежат рядом с проверяемым кодом, в `__tests__` соседней папки:

```
core/layout/
  visible-range.ts
  __tests__/
    visible-range.test.ts
```

Стиль — тот же, что в существующих: имя теста описывает поведение, а не метод.

```ts
it("не растит запас назад: там всё уже отрисовано", () => {
  // ...
});
```

Зависимости модулей передаются объектом опций, поэтому подмена в тесте — это
литерал, а не мок:

```ts
const range = computeVisibleRange({
  metrics,
  scroll: 1000,
  scrollLength: 500,
  drawDistance: 400,
  velocity: 2,
});
```
