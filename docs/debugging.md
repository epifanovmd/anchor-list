# Диагностика

Восемь каналов, по одному на механику. Все выключены по умолчанию и печатают в
одном формате.

Каждое событие печатает величины, по которым механика приняла решение. Симптом →
причина → что делать — в [troubleshooting.md](troubleshooting.md), стоимость за
окно — в [performance.md](performance.md).

---

## Включение

```ts
import { anchorListDebug, setAnchorListDebug } from "@epifanovmd/anchor-list";

anchorListDebug.help();                    // какие каналы бывают и что в них
setAnchorListDebug("mvcp");                // одна механика
anchorListDebug.help("mvcp");              // подписи всех её величин
```

`setAnchorListDebug` заменяет выбор целиком.

| Вызов | Что включает |
| --- | --- |
| `setAnchorListDebug(true)` | Все каналы |
| `setAnchorListDebug(false)` | Ничего |
| `setAnchorListDebug("mvcp")` | Один канал |
| `setAnchorListDebug(["mvcp", "layout"])` | Несколько каналов |
| `setAnchorListDebug({ scroll: ["jump"], mvcp: true })` | Отдельные события канала |

Точечные вызовы, когда выбор нужно менять по ходу:

```ts
anchorListDebug.enable("sticky");    // добавить к уже включённым
anchorListDebug.disable("sticky");   // убрать
anchorListDebug.only("edges");       // оставить один
anchorListDebug.off();               // выключить всё
anchorListDebug.status();            // что включено прямо сейчас
```

### Настройки печати

```ts
anchorListDebug.configure({
  maxLinesPerSecond: 120,        // потолок строк в секунду на всю диагностику
  sink: line => myLogger(line),  // куда печатать вместо консоли
});
```

Сверх потолка строки не печатаются, но считаются: число подавленных выходит
следующей строкой.

## Как читать строку

```
[mvcp·shift]        2.416 42    reason=данные candidate=0 moved=+18 applied=+18 lost=0
[mvcp·miss]!        2.418 42    before=120 after=138 error=18
```

| Колонка | Что это |
| --- | --- |
| `[mvcp·shift]` | Канал и событие в скобках — тот же ключ, что и у [замера](performance.md#что-в-отчёте) (`[list·метка]`): по нему строка опознаётся среди чужого вывода, а лог фильтруется по каналу целиком |
| `!` за скобкой | Событие говорит о **проблеме** — механика не сделала своего дела. Такие строки ищут первыми |
| `2.416` | Секунды от включения диагностики. Общая шкала всех каналов, в том числе тех, что печатает UI-поток |
| `42` | Ключ: за чем наблюдаем — индекс строки, кромка, номер контейнера. По нему же отсекаются повторы |
| дальше | Пары «величина=значение» в порядке объявления события |

Прочерк `—` означает, что величины нет, и это диагноз, а не пропуск колонки:
`anchor=—` у компенсации читается как «держать было не за что».

### Сколько строк печатает событие

У каждого события своя частота, и выбирал я её по тому, как часто оно случается:

| Режим | Где применяется |
| --- | --- |
| каждое | Редкие события, где важен сам факт: компенсация применена, кромка сработала, список показан |
| только изменения | Состояния: пока прилипший якорь тот же, повторять его геометрию нечем. Ведётся по каждому ключу отдельно |
| не чаще раза в интервал | Поток: событий скролла десятки в секунду, и печать каждого меняет то, что измеряется |

После повторного включения диагностики память о напечатанном сбрасывается.

### Обзор и подробности

Часть событий помечена **подробностями**: они не включаются вместе с каналом, их
нужно назвать по имени.

```ts
setAnchorListDebug("layout");                 // обзор механики
setAnchorListDebug({ layout: ["recycle"] });  // и поштучная переработка
```

Подробности — поштучные события: раздача контейнеров и переработка каждого из
них, по нескольку на кадр.

**Сводных чисел диагностика не считает** — это работа
[замера](performance.md).

Какие события подробности, видно в справке: `anchorListDebug.help()` печатает их
отдельной строкой, а `help("layout")` помечает каждое.

### Что отсекается по смыслу

- раздача контейнеров, ничего не изменившая, не печатается;
- высота контента печатается, только когда своя разошлась с нативной;
- замер строки печатается, только когда разошёлся с оценкой.

## Каналы

### `scroll` — движение смещения

Три представления о позиции: нативное смещение `ScrollView`, значение из события
и смещение, которым список считает скролл после компенсации.

| Событие | Когда печатается | На что смотреть |
| --- | --- | --- |
| `event` | Поток событий скролла, не чаще раза в 100 мс | `lag` — отставание представления списка от нативного слоя. Растущий лаг — причина пустот в кадре |
| `jump` ⚠ | Дельта выпала из ряда — на экране это рывок | Соседние строки других каналов объясняют, чем вызван: замером, компенсацией или своим переездом |
| `stale` | Событие отброшено как устаревшее | Много подряд — компенсация и события спорят за смещение |
| `program` | Список двигает сам себя | `target` и `from` дают длину прыжка |
| `atEnd` | Прилипание к концу: запрошено, отменено, выполнено | `wasAtEnd` — был ли пользователь у конца **до** изменения; `drift` — увёл ли список пользователь за кадр ожидания |
| `rest` | Движение кончилось, скорость обнулена | С этого момента снимается запас подрезки |

### `layout` — раскладка

Три шага: выбор диапазона, раздача контейнеров, замер нарисованного.

| Событие | Когда печатается | На что смотреть |
| --- | --- | --- |
| `range` | Диапазон изменился; не чаще раза в 200 мс | Строка вне `buffered` не нарисована — сколько её ни жди |
| `measure` | Замер строки разошёлся с оценкой | `delta` — на столько уедет всё, что ниже; `compensated=нет` на ходу означает видимый рывок |
| `blank` ⚠ | Часть вьюпорта нечем закрыть | `stage=до` — расчёт не поспел; `stage=после` — строк на это место нет вовсе |
| `content` | Своя высота контента разошлась с нативной | Значит замер отстал от раскладки, и граница скролла считается не по тому, что нарисовано |
| `bind` · подробность | Раздача контейнеров что-то изменила | `rebound` — цена прокрутки для React |
| `recycle` · подробность | Контейнер переиспользован под другой элемент | `sameType=нет` — поддерево перемонтируется целиком |

### `mvcp` — удержание видимой позиции

Цепочка: якорь снят до изменения → на сколько уехала его позиция → решение о
сдвиге → сдвиг применён.

| Событие | Когда печатается | На что смотреть |
| --- | --- | --- |
| `capture` | Якорь снят перед изменением | `candidates` — сколько запасных опор снято следом |
| `shift` | Компенсация посчитана и применена | `moved` — причина, `applied` — что доехало. Их расхождение и есть рывок |
| `noAnchor` ⚠ | Опоры не нашлось | `cause` различает «якорь не снят» и «снятые не пережили изменение» |
| `miss` ⚠ | Опора не осталась на месте | `error` — на столько строка уехала на экране |
| `skip` | Замер не компенсируется по скорости | Норма на броске; на медленном чтении — нет |

### `initial` — стартовая позиция и первый показ

Цель уточняется по кадрам, пока размеры не устаканятся.

| Событие | Когда печатается | На что смотреть |
| --- | --- | --- |
| `wait` | Цель ещё не вычислима | Много подряд — доводка ждёт данных, а не промахивается |
| `apply` | Попытка доводки | `arrived=нет` при неменяющемся `offset` — команду кто-то перебивает |
| `finish` | Доводка завершена | `reason=settled` — цель устоялась; иначе позиция посчитана по оценкам |
| `measure` | Замер, меняющий цель | `revealed=да` — перекладка на глазах у пользователя |
| `reveal` | Список показан | `cause` различает «доводка кончилась», «замеры пришли» и «сработала страховка» |

Обе строки `wait` и `apply` печатают всю цель целиком: тип, индекс, позицию,
размер, число элементов, высоту контента, начало координат, вьюпорт и версию
раскладки. Это ровно те величины, из которых цель и сложилась.

### `sticky` — прилипание

Цепочка `active` → `bind` → `offset`, плюс `pin` и `frame`/`overlay` — про две
копии якоря.

| Событие | Кто печатает | На что смотреть |
| --- | --- | --- |
| `active` | Ядро | Какой элемент прилип у кромки; `-1` — прилипать нечему |
| `bind` | Привязка контейнера | Расхождение `index` с `active` означает, что worklet считает по чужой строке |
| `pin` | Слой поверх контента | `rendered` ≠ `active` — застывший якорь на экране |
| `offset` | UI-поток | Состояние: `едет` · `стоит` · `вытеснен` · `уведён` |
| `frame` | UI-поток | Спрятана ли копия внутри контента и её экранная координата |
| `overlay` | UI-поток | Видима ли копия в слое. Видимы обе — двойник; скрыты обе — якорь пропал |

### `edges` — пороги подгрузки

Три решения между кромкой и колбэком: геометрия, защёлка кромки, общий гейт обеих
кромок.

| Событие | Когда печатается | На что смотреть |
| --- | --- | --- |
| `state` | Геометрия изменилась | Считает ли список расстояние так же, как видит пользователь |
| `reached` | Колбэк отправлен | `allowed` — какая кромка разблокирована жестом |
| `blocked` ⚠ | Кромка достигнута, но гейт не пропустил | Недавно сработала другая кромка: до нового жеста эта молчит |
| `suppressed` | Кромка в зоне, идёт своё движение списка | Во время своего движения пороги не проверяются |
| `reset` | Кромка снова готова сработать | `cause`: вышли за порог, контент вырос или новый жест |

### `view` — видимость элементов

| Событие | Когда печатается | На что смотреть |
| --- | --- | --- |
| `changed` | Набор видимых изменился и ушёл в колбэк | `entered` / `exited` — что именно изменилось |
| `hold` | Элемент ждёт `minimumViewTime` | Уведомления ещё не было |
| `drop` | Элемент ушёл раньше выдержки | Колбэка о нём не будет — и это законно |

### `insets` — нижний отступ

На каждом кадре хода клавиатуры список отдаёт место распоркой и на столько же
поднимает смещение. Печатает UI-поток.

| Событие | Когда печатается | На что смотреть |
| --- | --- | --- |
| `frame` | Кадр хода отступа | `to` — что просим; `owned` — позицией распоряжается жест, и смещение не наше дело |
| `settle` | Добор остатка после замера контента | `room` меньше `desired` — места ещё нет, повторять рано |

## Как сводить каналы между собой

Первая колонка у всех строк одна — секунды от включения. Типичные связки:

**Рывок на прокрутке.** `scroll·jump` даёт момент. Рядом ищутся
`layout·measure` — замер разошёлся с оценкой — и `mvcp·shift`: доехал ли сдвиг
до смещения. `mvcp·miss` показывает остаток, который и виден глазом.

**Пустая полоса в кадре.** `layout·blank` со `stage=до` означает, что расчёт не
поспел, и объясняется соседним `layout·range`: хватало ли `buffered`. Со
`stage=после` — строк на это место нет вовсе, и `range` это подтвердит.

**Строки перерисовываются чаще, чем нужно.** Сначала числа замера — `привязка` и
`рендеры`. Если перепривязок много, включается подробность:
`setAnchorListDebug({ layout: ["bind", "recycle"] })` — и видно, какие
контейнеры не попадают по типу.

**Якорь исчез.** `sticky·active` говорит, что ядро выбрало; `sticky·bind` — что
доехало до контейнера; `sticky·offset` — что посчитал worklet. Первое
расхождение и есть место ошибки.

**История не грузится.** `edges·blocked` называет причину прямо, а `edges·state`
показывает, действительно ли до кромки близко.

## Цена

Выключенная диагностика — одна проверка признака на точку печати. Включённая
стоит кадров: сбор величин, форматирование и вывод в консоль. Печать из
worklet-а (`sticky`, `insets`) дороже прочей. Сравнивать по логу нужно числа, а
не ощущение плавности.

## Как добавить событие

Событие живёт в файле своего канала — `src/debug/channels/`. Канал объявляет
события, событие объявляет свои величины, каждая величина подписана; из этих же
объявлений собирается справка.

```ts
export const logMvcpShift = mvcpDebug.event("shift", {
  about: "компенсация посчитана и применена",
  key: "anchor",
  fields: {
    anchor: "индекс опоры, по которой считали",
    moved: "на сколько уехала позиция якоря, px",
    applied: "сколько из moved доехало до смещения",
  },
});
```

Требования к событию, которые проверяются тестами:

1. печатает всё, из чего сложилось решение, а не только итог;
2. `detail: true` у поштучных событий — тех, что случаются по нескольку раз на
   кадр; каналом целиком они не включаются;
3. `repeat` — `"always"`, `"changes"` или `{ everyMs }`; `compare` называет
   величины, по которым строка считается изменившейся;
4. `problem: true` — только там, где механика не сделала своего дела;
5. каждая величина подписана, имена величин латиницей.

Событие, которое печатает UI-поток, объявляется через `worklet(...)` — оно
попадает в справку наравне с остальными, а печатается через `logFromWorklet`
тем же форматом.
