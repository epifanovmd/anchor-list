# Прилипание

Якоря, останавливающиеся у кромки вьюпорта. Заголовки дат сверху, аватары групп
снизу — можно и то и другое одновременно.

## Конфигурация

```ts
interface IAnchorListStickyConfig<TItem = unknown> {
  edge: "start" | "end";
  indices: number[];
  offset?: SharedValue<number>;
  mode?: "container" | "offset";
  size?: number;
  groupStarts?: number[];
  limitInset?: number;
  renderOverlay?: (item: TItem, index: number) => ReactNode;
}
```

`sticky` — массив таких наборов. **На каждой кромке — не более одного набора.**

```tsx
const sticky = useMemo<IAnchorListStickyConfig<ChatRow>[]>(
  () => [{ edge: "start", indices: dayIndices }],
  [dayIndices],
);

<AnchorList sticky={sticky} ... />;
```

Массив и объекты внутри сравниваются по ссылке — мемоизируйте.

## Индексы

`indices` — индексы якорных строк в **текущих** данных, **по возрастанию**.

Их считает тот, кто строит данные. Если сверху появился спиннер, все индексы
сдвинулись на единицу:

```tsx
const dayIndices = useMemo(
  () => (loadingStart ? indices.map(index => index + 1) : indices),
  [indices, loadingStart],
);
```

Это самый частый источник ошибок: якорями оказываются соседние строки, и на
экране липнет не то.

## Отступ кромки

`offset` — динамический отступ от кромки: навбар сверху, панель ввода,
клавиатура и безопасная зона снизу. Поэтому это shared value, а не число: оно
меняется вместе с клавиатурой, и якорь обязан ехать с ней в один кадр.

**У конечной кромки его можно не задавать.** Если `offset` не указан, список
подставит свой [`insetEnd`](props.md#insetend-sharedvaluenumber) — то же число,
каким снизу ограничены контент и индикатор скролла. Прилипший якорь тогда
останавливается на одной линии с последней строкой, а не под панелью. Свой
`offset` приоритетнее.

У начальной кромки умолчания нет: сверху вьюпорт обычно ничем не занят — список
и так начинается под навбаром, — а если заходит под него, высоту знает только
вызывающий.

```tsx
const topOffset = useSharedValue(0);

// Навбар померялся — якорь останавливается под ним, а не под кромкой экрана.
topOffset.value = navbarHeight;
```

## Режим `container`

По умолчанию. Прилипает вся строка целиком: заголовки, разделители дат.

```tsx
const sticky = useMemo<IAnchorListStickyConfig<ChatRow>[]>(
  () => [{ edge: "start", indices: dayIndices, offset: topOffset }],
  [dayIndices, topOffset],
);
```

Делать больше ничего не нужно: `renderItem` уже умеет рисовать эту строку, и
прилипшая копия по умолчанию берётся из него же.

### Как ведёт себя якорь

У начальной кромки якорь сдвигается вниз ровно настолько, насколько кромка его
обогнала, и упирается в **предел** — точку, где подъезжающий снизу следующий
якорь выталкивает его за кромку.

У конечной кромки зеркально: якорь поднимается, когда его низ уходит ниже кромки,
и не может подняться выше начала своей группы.

Предел считается для каждого якоря и зависит только от геометрии соседей, но не
от позиции скролла: иначе значение менялось бы на каждом кадре прокрутки и
дёргало worklet прилипания.

## Режим `offset`

Строка остаётся на месте, а прилипает **объект внутри неё**. Так прилипает аватар
группы, не утаскивая за собой сообщение.

```tsx
const sticky = useMemo<IAnchorListStickyConfig<ChatRow>[]>(
  () => [
    {
      edge: "end",
      indices: avatarIndices,
      offset: bottomOffset,
      mode: "offset",
      size: AVATAR_SIZE,
      groupStarts,
      limitInset: MESSAGE_GAP,
      renderOverlay: item => <PinnedAvatar row={item} />,
    },
  ],
  [avatarIndices, groupStarts, bottomOffset],
);
```

Смещение приходит в `renderItem` shared value — ячейка применяет его к нужному
узлу:

```tsx
const renderItem = useCallback(
  ({ item, stickyOffset, stickyPinned }: IAnchorListRenderItemProps<ChatRow>) => (
    <ChatRow row={item} stickyOffset={stickyOffset} stickyPinned={stickyPinned} />
  ),
  [],
);
```

```tsx
// Внутри строки маппер заводится только у якорной строки, а не у каждой.
const style = useAnimatedStyle(() => ({
  opacity: stickyPinned?.value ? 0 : 1,
  transform: [{ translateY: stickyOffset?.value ?? 0 }],
}));

<Animated.View style={style}>
  <Avatar name={row.author} />
</Animated.View>;
```

### `size`

Высота прилипающего объекта — например аватара, а не всей строки. От неё зависит,
докуда объект поднимается: его верх не должен выходить за начало своей группы.

По умолчанию берётся высота строки, что для аватара внутри высокого сообщения
неверно.

### `groupStarts`

Индекс первой строки группы для каждого якоря — **параллельно `indices`**, той же
длины и в том же порядке.

Задаёт границу, выше которой объект не поднимается. Без него границей считается
строка сразу за предыдущим якорем, а между якорями могут лежать разделители дат и
чужие сообщения — тогда аватар уезжает за пределы своей группы.

```tsx
// indices:     [3, 7, 12]  — хвосты групп, где рисуется аватар
// groupStarts: [1, 5,  9]  — первые сообщения тех же групп
```

### `limitInset`

Сдвиг верхней границы группы вниз, px.

Нужен, когда зазор между строками создаётся отступом **внутри** них: габариты
строки тогда выше видимого содержимого, и без поправки объект поднимается в этот
зазор.

Если в строке `marginTop: 8` у пузыря сообщения — `limitInset: 8`.

### `renderOverlay`

В режиме `offset` **обязателен**: у кромки стоит не строка, а объект внутри неё,
и копию должен нарисовать вызывающий.

Горизонтальные отступы копии обязаны повторять слот объекта в строке — иначе
копия встанет не на то место, откуда исчез оригинал:

```tsx
const PinnedAvatar = ({ row }) => (
  // paddingLeft и width повторяют слот аватара в ChatRow
  <View style={{ paddingLeft: 12, width: 56 }}>
    <Avatar name={row.author} size={36} />
  </View>
);
```

В режиме `container` необязателен: по умолчанию копия берётся из `renderItem`.

## Слой прилипших копий

Это то, из-за чего прилипание здесь не дрожит.

### Проблема

Якорь у кромки обязан стоять на месте **экрана**, а всё внутри `ScrollView` едет
вместе с контентом. Держаться на месте там можно только покадровой компенсацией
скролла: `translateY` пересчитывается на каждом кадре из текущего смещения.

Любой пропущенный кадр доставки события такую компенсацию рвёт, и это видно как
дрожание.

### Решение

У прилипания три состояния, и покадровое движение есть только в одном из них:

| Состояние | Что делает трансформ | Кто везёт элемент |
| --- | --- | --- |
| Якорь ещё не доехал до кромки | Постоянен (`0`) | Нативный скролл |
| Якорь стоит у кромки | Меняется каждый кадр | Покадровая компенсация |
| Якорь выталкивается следующим | Постоянен (упёрся в предел) | Нативный скролл |

Среднее состояние отдаётся отдельному слою поверх списка — снаружи `ScrollView`,
на постоянной позиции и вовсе без покадрового трансформа. Копия внутри контента в
этот момент прячется, оставаясь на месте для касаний.

Так покадровая компенсация исчезает совсем, а вместе с ней — рывки от
пропущенных кадров скролла и от чужих коммитов.

### Что из этого следует для вызывающего

`stickyPinned` — это «слой уже нарисовал копию, свою нужно спрятать». Прятать
надо **прозрачностью, а не размонтированием**: узел остаётся на месте, иначе
поедет раскладка строки и пропадут касания.

```tsx
opacity: stickyPinned?.value ? 0 : 1  // да
{!stickyPinned?.value && <Avatar />}  // нет
```

Сверка идёт по факту отрисовки слоем, а не по факту доезда до кромки: слой узнаёт
о новом якоре из рендера, то есть на коммит позже, и без этой сверки на стыке
оставался бы кадр, где не нарисован ни один из двух.

## Активный якорь наружу

```tsx
const activeStickyStartIndex = useSharedValue(-1);

<AnchorList
  sticky={sticky}
  sharedValues={useMemo(
    () => ({ activeStickyStartIndex }),
    [activeStickyStartIndex],
  )}
/>;
```

`-1` — якорей нет. То же доступно через `state`:
`useAnchorListValue(state, "activeStickyStartIndex")`.

---

## Стоимость

Reanimated-инфраструктура стоит мапперов на каждый кадр, поэтому прилипающий
элемент оборачивается в отдельный компонент с мапперами, а обычный — в простую
`View`. Заводить мапперы для всех строк нельзя.

Соседей активного якоря список держит смонтированными по обе стороны, даже за
пределами видимого диапазона: иначе якорь исчезал бы в момент, когда его уже
пора показывать.

Что прилипание стоит на проходе, видно в строке `стики` встроенного замера.

## Если что-то идёт не так

Прилипание считается в трёх местах сразу, и по экрану не сказать, какое из них
ошиблось. Есть диагностика, печатающая все три:
[Диагностика](troubleshooting.md#прилипание-ведёт-себя-странно-а-причина-не-видна).
