# Отступы и клавиатура

Панель ввода и клавиатура съедают низ вьюпорта. Список об этом сам не знает — ему
нужно сказать. Сказать один раз: всё, что упирается в низ, он считает от одного
значения — `insetEnd`.

## Задача

```
┌─────────────────┐
│    навбар       │
├─────────────────┤
│                 │
│    сообщения    │  ← контент обязан кончаться здесь
│                 │
├─────────────────┤
│  панель ввода   │
├─────────────────┤
│                 │
│   клавиатура    │
│                 │
└─────────────────┘
```

До низа экрана дотягиваются четверо, и каждому нужно своё:

| Кто | Что ему нужно |
| --- | --- |
| **Контент** | Кончаться над панелью — место отдаёт распорка в конце контента |
| **Скролл** | Подняться вместе с клавиатурой, иначе последняя строка уедет под неё |
| **Индикатор скролла** | Живёт в координатах `ScrollView` и о распорке не знает |
| **Прилипший якорь конечной кромки** | По умолчанию встаёт у самого низа вьюпорта, то есть под панелью |

Считай каждый отдельно — получится столько же расходящихся ответов, и
расхождение видно глазом. Поэтому величина одна, и раздаёт её список.

## Перекрытие снизу — один источник

```tsx
/** Перекрытие: клавиатура либо безопасная зона. */
const occludedBottom = useDerivedValue(() =>
  Math.max(keyboardHeight.value, safeAreaBottom),
);

/** Полное перекрытие: зона плюс панель ввода. */
const contentInset = useDerivedValue(
  () => occludedBottom.value + barHeight.value,
);
```

**Максимум, а не сумма.** Открытая клавиатура сама закрывает домашний индикатор,
и добавлять его отступ поверх неё нечего.

**Перекрытие можно заморозить.** Пока оно держится на закрытом положении —
безопасная зона плюс панель, — список о клавиатуре не знает и раскладку не
трогает. Так делают там, где клавиатура закрылась не насовсем: поле ввода
потеряло фокус под всплывающей панелью, и дёргать список туда-обратно не за чем.

Готовые хуки в примере:
[`useKeyboardHeight`](../example/src/ui/useKeyboardHeight.ts) — сырая высота
покадрово, [`useKeyboardInset`](../example/src/ui/useKeyboardInset.ts) — само
перекрытие: одна подписка на клавиатуру на экран, заморозка тумблером `enabled`,
и от него считают все.

## 1. Список — `insetEnd`

```tsx
<AnchorList insetEnd={contentInset} ... />
```

Одно посчитанное значение — и всё, что упирается в низ, считает от него. Список
сам:

- **ставит распорку в конце контента.** Она часть контента, поэтому последняя
  строка честно останавливается над панелью, а `scrollToEnd` и автоприлипание к
  концу считаются без поправок;
- **вычитает отступ из выравнивания** ([`alignItemsAtEnd`](scrolling.md#alignitemsatend)):
  короткий контент прижимается к верху панели, а не к низу экрана;
- **поднимает смещение** вместе с отступом, когда контент длиннее экрана;
- **отодвигает индикатор скролла**, который живёт в координатах `ScrollView` и о
  распорке не знает;
- **отодвигает якорь конечной кромки**, который иначе встаёт под панелью.

Всё это считается на UI-потоке, в такт клавиатуре: через JS раскладка отставала
бы на кадр, и это видно рывком. Поэтому и shared value, а не число — величина
одинаково годится и для статики (безопасная зона), и для покадрового хода
клавиатуры.

### Кто именно поднимает контент

Подъём делят между собой двое, и делят его по одному правилу: **низ контента
обязан стоять на верхней кромке панели.**

**Контента меньше экрана — поднимает сдвиг выравнивания.** Прокручивать в таком
списке нечего, и скроллу двигать нечем: сдвиг просто становится меньше на столько
же, на сколько вырос отступ.

**Контента больше — поднимает скролл.** Распорка в конце даёт ему место, и
смещение растёт на ту же величину, что и отступ.

**На границе они делят подъём.** Сдвиг доезжает до нуля, дальше добирает скролл;
обе величины считаются в одном кадре из одного и того же отступа, поэтому в сумме
дают ровно его прирост — ни больше, ни меньше.

**Одной распорки мало.** Она добавляется в **конец** контента, а
[удержание позиции](maintain-position.md) компенсирует только изменения выше
вьюпорта — видимые строки от неё не двигаются, и последняя остаётся там же,
просто под ней появляется место. Поэтому список поднимает смещение явно.

**Высота контента считается по своим размерам, а не по замеру.** Замер
`contentSize` приходит через JS и отстаёт на кадр-другой, а на ходу клавиатуры
это ровно та величина, по которой решается, докуда двигать контент. По
отставшему замеру диапазон выходит короче настоящего, сдвиг обрезается — и
контент остаётся ниже, чем должен.

**Низ, стоявший на кромке, там и остаётся.** Смещение приходит от нативного
скролла квантованным — на экране 3× это трети точки. Складывать дельты на таких
долях значит терять их из хода в ход: за несколько открытий клавиатуры контент
отползает от кромки на видимый зазор. Поэтому у самого низа смещение считается
не сложением, а прямо от границы контента.

**Распорка идёт на пару кадров впереди отступа.** Её высота едет через дерево
раскладки и применяется уже после того, как в этом же кадре отработал сдвиг
смещения. У самого низа, где смещение стоит ровно на границе, запрос из-за этого
обрезается по прежней высоте — контент отстаёт от клавиатуры на кадр. Запас
впереди убирает обрез: он весь ниже последней строки и не виден, а как только
движение кончилось — сходит в ноль.

**Жест приоритетнее.** Пока палец на экране или идёт инерция, позицией управляет
жест: свою фазу жеста список знает сам, подключать для этого ничего не нужно.

## 2. Кнопка «вниз» — живое перекрытие

```tsx
const buttonStyle = useAnimatedStyle(() => ({
  opacity: withTiming(isAtEnd.value ? 0 : 1),
  transform: [{ translateY: -(contentInset.value + GAP) }],
  pointerEvents: isAtEnd.value ? "none" : "auto",
}));
```

Кнопка берёт то же перекрытие, что и список, — и едет с ним в один кадр.

Двигать надо трансформом, а не `bottom`: тот пересчитывал бы раскладку на каждом
кадре. `pointerEvents` задаётся стилем, а не пропом: видимость считается на
UI-потоке, и React не должен перехватывать тапы скрытой кнопки.

Видимость берётся из `sharedValues.isWithinMaintainScrollAtEndThreshold` — тогда
кнопка и автоприлипание согласованы по определению.

## 3. Панель ввода

```tsx
const composerStyle = useAnimatedStyle(() => ({
  // Зона гасится ровно настолько, насколько её перекрыла клавиатура: иначе
  // между строкой ввода и клавишами остаётся пустая полоса.
  paddingBottom: occludedBottom.value - keyboardHeight.value,
  transform: [{ translateY: -keyboardHeight.value }],
}));
```

Полный след панели от низа экрана — `occludedBottom + barHeight`, то есть ровно
`contentInset`. Круг замкнулся.

## Откуда брать положение клавиатуры

Списку всё равно, откуда приходит shared value, — важно лишь, чтобы она менялась
на UI-потоке.

**`react-native-keyboard-controller` — рекомендуемый способ.** Отдаёт положение
покадрово и сразу shared value, включая закрытие свайпом, а в `onStart` — ещё и
длительность анимации: покадровые события приходят не на всех платформах, и без
доводки по ней движение было бы ступенчатым.

```tsx
import { useKeyboardHandler } from "react-native-keyboard-controller";

useKeyboardHandler({
  onStart: event => {
    "worklet";

    // Покадровые события приходят не на всех платформах: без доводки
    // анимацией движение было бы ступенчатым.
    height.value = withTiming(event.height, { duration: event.duration });
  },
  onMove: event => {
    "worklet";

    height.value = event.height;
  },
  // Закрытие свайпом по списку: высота идёт за пальцем.
  onInteractive: event => {
    "worklet";

    height.value = event.height;
  },
  onEnd: event => {
    "worklet";

    height.value = event.height;
  },
});
```

Приложение оборачивается в `KeyboardProvider`.

Событиями React Native (`Keyboard.addListener`) обойтись можно, но высоту они
дают только в момент показа, длительность приходится подбирать на глаз, а
закрытие свайпом не отслеживается вовсе.

## Прилипание и отступы

Отступ конечной кромки подставляется из `insetEnd` сам. Задавать его вручную
нужно только там, где он отличается, — и у начальной кромки, где умолчания нет:

```tsx
const sticky = useMemo<IAnchorListStickyConfig<ChatRow>[]>(
  () => [
    // Список уходит под навбар — эту высоту знает только вызывающий.
    { edge: "start", indices: dayIndices, offset: navbarHeight },
    // Отступ не задан: подставится `insetEnd`.
    { edge: "end", indices: avatarIndices, mode: "offset" },
  ],
  [dayIndices, avatarIndices, navbarHeight],
);
```

## Верхний отступ

Навбар над списком — это просто раскладка снаружи: `AnchorList` с `flex: 1` под
навбаром. Списку про верхний отступ знать не нужно.

Он нужен только прилипанию: `sticky[].offset` для `edge: "start"` — это высота
навбара, если список уходит под него.

## Частые ошибки

| Симптом | Причина |
| --- | --- |
| Последняя строка под панелью ввода | Не передан `insetEnd` |
| Двойной отступ снизу, короткий список прокручивается | Распорка осталась в `ListFooterComponent`: место под `insetEnd` список отдаёт сам |
| Контент дёргается вместо движения с клавиатурой | Значение считается в JS и приходит рендером — нужен shared value, меняющийся на UI-потоке |
| Кнопка «вниз» уезжает раньше клавиатуры или виснет наверху | Взята не та величина: ей нужно живое перекрытие |
| Индикатор скролла доходит до низа экрана | Не передан `insetEnd` |
| На iOS индикатор кончается слишком высоко | Safe area посчитана дважды: она уже входит в `insetEnd` |
| Между строкой ввода и клавишами пустая полоса | Безопасная зона не гасится по мере перекрытия клавиатурой |

## Проверить руками

Стенд «Нижний отступ» в [`example/`](../example): компенсация отключается
тумблером — видно, как контент уходит под панель без неё. Проверять стоит три
состояния, они держатся на разных механиках: короткий список (поднимает
выравнивание, прокрутки нет вовсе), длинный у самого низа (поднимает скролл) и
список чуть длиннее экрана — там подъём делят оба.
