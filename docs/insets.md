# Отступы и клавиатура

Всё, что упирается в низ вьюпорта, список считает от одного значения —
`insetEnd`.

```
┌─────────────────┐
│    навбар       │
├─────────────────┤
│                 │
│    сообщения    │  ← контент кончается здесь
│                 │
├─────────────────┤
│  панель ввода   │
├─────────────────┤
│                 │
│   клавиатура    │
│                 │
└─────────────────┘
```

| Кто | Что ему нужно |
| --- | --- |
| **Контент** | Кончаться над панелью — место отдаёт распорка в конце контента |
| **Скролл** | Подняться вместе с клавиатурой |
| **Индикатор скролла** | Живёт в координатах `ScrollView` и о распорке не знает |
| **Прилипший якорь конечной кромки** | Иначе встаёт под панелью |

## Перекрытие снизу

```tsx
/** Перекрытие: клавиатура либо безопасная зона. */
const occludedBottom = useDerivedValue(() =>
  Math.max(keyboardHeight.value, safeAreaBottom),
);

/** Полное перекрытие: зона плюс панель ввода. */
const contentInset = useDerivedValue(
  () => occludedBottom.value + barHeight.value,
);
```

**Максимум, а не сумма:** открытая клавиатура сама закрывает домашний индикатор.

Перекрытие можно заморозить на закрытом положении (безопасная зона плюс панель) —
тогда список о клавиатуре не знает и раскладку не трогает.

Готовые хуки в примере:
[`useKeyboardHeight`](../example/src/ui/useKeyboardHeight.ts) — сырая высота
покадрово, [`useKeyboardInset`](../example/src/ui/useKeyboardInset.ts) — само
перекрытие с заморозкой по `enabled`.

## 1. Список — `insetEnd`

```tsx
<AnchorList insetEnd={contentInset} ... />
```

От этого значения список сам:

- **ставит распорку в конце контента** — она часть контента, поэтому последняя
  строка останавливается над панелью, а `scrollToEnd` и автоприлипание к концу
  считаются без поправок;
- **вычитает отступ из выравнивания**
  ([`alignItemsAtEnd`](scrolling.md#alignitemsatend));
- **поднимает смещение** вместе с отступом, когда контент длиннее экрана;
- **отодвигает индикатор скролла**;
- **отодвигает якорь конечной кромки**.

Тип — shared value: всё перечисленное считается на UI-потоке и едет с клавиатурой
в один кадр. Значение, посчитанное в JS и приходящее рендером, отстаёт.

### Кто поднимает контент

Правило одно: **низ контента стоит на верхней кромке панели.**

**Контента меньше экрана — поднимает сдвиг выравнивания.** Прокручивать нечего,
сдвиг становится меньше ровно на прирост отступа.

**Контента больше — поднимает скролл.** Распорка в конце даёт место, смещение
растёт на величину отступа.

**На границе они делят подъём:** сдвиг доезжает до нуля, остаток добирает скролл.
Обе величины считаются в одном кадре из одного отступа.

Дополнительно:

- **Одной распорки мало:** она добавляется в конец, а
  [удержание позиции](maintain-position.md) компенсирует только изменения выше
  вьюпорта. Смещение список поднимает явно.
- **Высота контента считается по своим размерам**, а не по замеру `contentSize`,
  который отстаёт на кадр-другой.
- **У самого низа смещение считается от границы контента**, а не сложением
  дельт.
- **Распорка идёт на пару кадров впереди отступа** и сходит в ноль, когда
  движение кончилось.
- **Жест приоритетнее:** пока палец на экране или идёт инерция, позицией
  управляет жест.
- **До первого показа отступ смещения не трогает**, но учитывается к моменту
  показа.

## 2. Кнопка «вниз»

```tsx
const buttonStyle = useAnimatedStyle(() => ({
  opacity: withTiming(isAtEnd.value ? 0 : 1),
  transform: [{ translateY: -(contentInset.value + GAP) }],
  pointerEvents: isAtEnd.value ? "none" : "auto",
}));
```

Кнопка берёт то же перекрытие, что и список. Двигать её нужно трансформом, а не
`bottom`; `pointerEvents` задаётся стилем, потому что видимость считается на
UI-потоке.

Видимость берётся из `sharedValues.isWithinMaintainScrollAtEndThreshold` — того
же порога, по которому работает автоприлипание.

## 3. Панель ввода

```tsx
const composerStyle = useAnimatedStyle(() => ({
  // Зона гасится ровно настолько, насколько её перекрыла клавиатура.
  paddingBottom: occludedBottom.value - keyboardHeight.value,
  transform: [{ translateY: -keyboardHeight.value }],
}));
```

Полный след панели от низа экрана — `occludedBottom + barHeight`, то есть
`contentInset`.

## Откуда брать положение клавиатуры

Требование одно: shared value, меняющаяся на UI-потоке.

**`react-native-keyboard-controller`** отдаёт положение покадрово, включая
закрытие свайпом, а в `onStart` — длительность анимации:

```tsx
import { useKeyboardHandler } from "react-native-keyboard-controller";

useKeyboardHandler({
  onStart: event => {
    "worklet";

    // Покадровые события приходят не на всех платформах: без доводки
    // анимацией движение было бы ступенчатым.
    height.value = withTiming(event.height, { duration: event.duration });
  },
  onMove: event => {
    "worklet";

    height.value = event.height;
  },
  // Закрытие свайпом по списку: высота идёт за пальцем.
  onInteractive: event => {
    "worklet";

    height.value = event.height;
  },
  onEnd: event => {
    "worklet";

    height.value = event.height;
  },
});
```

Приложение оборачивается в `KeyboardProvider`.

`Keyboard.addListener` из React Native даёт высоту только в момент показа, без
длительности и без закрытия свайпом.

## Прилипание и отступы

Отступ конечной кромки подставляется из `insetEnd`. Задавать вручную нужно
только там, где он отличается, и у начальной кромки:

```tsx
const sticky = useMemo<IAnchorListStickyConfig<ChatRow>[]>(
  () => [
    // Список уходит под навбар — эту высоту знает только вызывающий.
    { edge: "start", indices: dayIndices, offset: navbarHeight },
    // Отступ не задан: подставится `insetEnd`.
    { edge: "end", indices: avatarIndices, mode: "offset" },
  ],
  [dayIndices, avatarIndices, navbarHeight],
);
```

## Верхний отступ

Навбар над списком — раскладка снаружи: `AnchorList` с `flex: 1` под навбаром.
Списку верхний отступ не нужен; он нужен прилипанию — `sticky[].offset` для
`edge: "start"`.

## Частые ошибки

| Симптом | Причина |
| --- | --- |
| Последняя строка под панелью ввода | Не передан `insetEnd` |
| Двойной отступ снизу, короткий список прокручивается | Распорка осталась в `ListFooterComponent` |
| Контент дёргается вместо движения с клавиатурой | Значение считается в JS и приходит рендером |
| Кнопка «вниз» уезжает раньше клавиатуры | Взята не та величина: нужно живое перекрытие |
| Индикатор скролла доходит до низа экрана | Не передан `insetEnd` |
| На iOS индикатор кончается слишком высоко | Safe area посчитана дважды: она уже входит в `insetEnd` |
| Между строкой ввода и клавишами пустая полоса | Безопасная зона не гасится по мере перекрытия |

## Проверить руками

Стенд «Нижний отступ» в [`example/`](../example): компенсация отключается
тумблером. Три состояния держатся на разных механиках — короткий список
(поднимает выравнивание), длинный у самого низа (поднимает скролл) и список чуть
длиннее экрана (подъём делят оба).
