# Отступы и клавиатура

Панель ввода и клавиатура съедают низ вьюпорта. Список об этом сам не знает — ему
нужно сказать, и сказать в нескольких местах сразу.

## Задача

```
┌─────────────────┐
│    навбар       │
├─────────────────┤
│                 │
│    сообщения    │  ← контент обязан кончаться здесь
│                 │
├─────────────────┤
│  панель ввода   │
├─────────────────┤
│                 │
│   клавиатура    │
│                 │
└─────────────────┘
```

До низа экрана дотягиваются четверо, и каждый считает отступ по-своему:

| Кто | Что ему нужно |
| --- | --- |
| **Контент** | Кончаться над панелью — место отдаётся распоркой в подвале |
| **Скролл** | Подняться вместе с клавиатурой, иначе последняя строка уедет под неё |
| **Индикатор скролла** | Живёт в координатах `ScrollView` и о распорке не знает |
| **Прилипший якорь конечной кромки** | По умолчанию встаёт у самого низа вьюпорта, то есть под панелью |

Если хоть один считает отступ отдельно, расхождение видно глазом. Поэтому
величина должна быть одна.

## Перекрытие снизу — один источник

```tsx
/** Перекрытие: клавиатура либо безопасная зона. */
const occludedBottom = useDerivedValue(() =>
  Math.max(keyboardHeight.value, safeAreaBottom),
);

/** Полное перекрытие: зона плюс панель ввода. */
const contentInset = useDerivedValue(
  () => occludedBottom.value + barHeight.value,
);
```

**Максимум, а не сумма.** Открытая клавиатура сама закрывает домашний индикатор,
и добавлять его отступ поверх неё нечего.

Готовые хуки в примере:
[`useKeyboardHeight`](../example/src/ui/useKeyboardHeight.ts) — сырая высота,
[`useKeyboardInset`](../example/src/ui/useKeyboardInset.ts) — перекрытие.

## 1. Контент — распорка **и сдвиг скролла**

Место под панелью отдаётся списку распоркой в подвале: она часть контента,
поэтому последняя строка честно останавливается над панелью.

**Одной распорки мало.** Она добавляется в **конец** контента, а
[удержание позиции](maintain-position.md) компенсирует только изменения выше
вьюпорта — видимые строки от неё не двигаются, и последняя остаётся там же,
просто под ней появляется место. Чтобы контент поднялся вместе с клавиатурой,
смещение сдвигается явно, на ту же дельту и на UI-потоке: через JS сдвиг
опоздал бы на кадр и был бы виден рывком.

Три условия, без которых сдвиг ломается:

**Место резервируется заранее.** `scrollTo` не уводит скролл дальше границы
контента. Высота распорки проходит через раскладку, а размер контента отстаёт на
кадр: у самого низа списка сдвиг упрётся в ещё не выросший диапазон и обрежется —
компенсация пропадёт ровно там, где нужнее всего. Целевая высота клавиатуры
известна до начала движения, по ней и резервируют:

```tsx
const reservedInset = useDerivedValue(
  () => Math.max(targetHeight.value, safeAreaBottom) + barHeight.value,
);
```

Та же формула, только на целевой высоте вместо текущей. Считать резерв иначе —
запоминать максимум и сбрасывать в конце — значит получить ту же величину с
ручной бухгалтерией: при закрытии такой резерв держит открытое значение всю
анимацию, и распорка схлопывается разом в самом конце.

**Конец контента считается сам.** Замер `contentSize` придёт только следующим
кадром, а сдвинуть нужно уже сейчас — иначе всё упирается в нативное обрезание,
которое и съедает сдвиг у нижней границы.

**Жест приоритетнее.** Пока палец на экране, позицией управляет он, и
компенсация обязана не вмешиваться: подключаются `onScrollBeginDrag` и
`onScrollEndDrag`.

Всё вместе — в
[`useKeyboardScrollCompensation`](../example/src/ui/useKeyboardScrollCompensation.ts):

```tsx
const compensation = useKeyboardScrollCompensation(contentInset, reservedInset);

<AnchorList
  refScrollView={compensation.scrollRef}
  onLayout={compensation.onLayout}
  onContentSizeChange={compensation.onContentSizeChange}
  onScrollBeginDrag={compensation.onScrollBeginDrag}
  onScrollEndDrag={compensation.onScrollEndDrag}
  ListFooterComponent={
    <Animated.View style={compensation.spacerStyle} pointerEvents={"none"} />
  }
/>;
```

## 2. Индикатор скролла и прилипание — `insetEnd`

```tsx
<AnchorList insetEnd={compensation.contentInset} ... />
```

Один проп на двоих:

- **индикатор скролла** живёт в координатах `ScrollView` и без него доходит до
  кромки экрана, тогда как контент останавливается над панелью;
- **якорь конечной кромки** по умолчанию берёт этот же отступ и останавливается
  над панелью, а не под ней. Набор прилипания может задать свой `offset` — он
  приоритетнее. См. [Прилипание](sticky.md#отступ-кромки).

Передаётся **высота распорки** (`compensation.contentInset`), а не живое
перекрытие: индикатор и якорь обязаны кончаться там же, где кончается контент.

**Про iOS.** Система сама добавляет safe area к инсетам индикатора. Здесь она уже
входит в переданное значение, поэтому при заданном `insetEnd` список отключает
`automaticallyAdjustsScrollIndicatorInsets` — иначе отступ был бы двойным.

## 3. Кнопка «вниз» — живое перекрытие

```tsx
const buttonStyle = useAnimatedStyle(() => ({
  opacity: withTiming(isAtEnd.value ? 0 : 1),
  transform: [{ translateY: -(contentInset.value + GAP) }],
  pointerEvents: isAtEnd.value ? "none" : "auto",
}));
```

Здесь берётся **живое** перекрытие, а не высота распорки: та по устройству
прыгает к цели сразу, и кнопка уехала бы вверх раньше клавиатуры, а при закрытии
повисла бы наверху до конца анимации.

Двигать надо трансформом, а не `bottom`: тот пересчитывал бы раскладку на каждом
кадре. `pointerEvents` задаётся стилем, а не пропом: видимость считается на
UI-потоке, и React не должен перехватывать тапы скрытой кнопки.

Видимость берётся из `sharedValues.isWithinMaintainScrollAtEndThreshold` — тогда
кнопка и автоприлипание согласованы по определению.

## 4. Панель ввода

```tsx
const composerStyle = useAnimatedStyle(() => ({
  // Зона гасится ровно настолько, насколько её перекрыла клавиатура: иначе
  // между строкой ввода и клавишами остаётся пустая полоса.
  paddingBottom: occludedBottom.value - keyboardHeight.value,
  transform: [{ translateY: -keyboardHeight.value }],
}));
```

Полный след панели от низа экрана — `occludedBottom + barHeight`, то есть ровно
`contentInset`. Круг замкнулся.

## Откуда брать положение клавиатуры

Списку всё равно, откуда приходит shared value, — важно лишь, чтобы она менялась
на UI-потоке.

**`react-native-keyboard-controller` — рекомендуемый способ.** Отдаёт положение
покадрово и сразу shared value, включая закрытие свайпом, и — что важнее —
целевую высоту в `onStart`, до начала движения:

```tsx
import { useKeyboardHandler } from "react-native-keyboard-controller";

useKeyboardHandler({
  onStart: event => {
    "worklet";

    targetHeight.value = event.height;
    // Покадровые события приходят не на всех платформах: без доводки
    // анимацией движение было бы ступенчатым.
    height.value = withTiming(event.height, { duration: event.duration });
  },
  onMove: event => {
    "worklet";

    height.value = event.height;
  },
  onInteractive: event => {
    "worklet";

    targetHeight.value = event.height;
    height.value = event.height;
  },
  onEnd: event => {
    "worklet";

    targetHeight.value = event.height;
    height.value = event.height;
  },
});
```

Приложение оборачивается в `KeyboardProvider`.

Событиями React Native (`Keyboard.addListener`) обойтись можно, но целевую высоту
они дают только в момент показа, длительность приходится подбирать на глаз, а
закрытие свайпом не отслеживается вовсе — резерв места тогда не построить.

## Прилипание и отступы

Отступ конечной кромки подставляется из `insetEnd` сам. Задавать его вручную
нужно только там, где он отличается, — и у начальной кромки, где умолчания нет:

```tsx
const sticky = useMemo<IAnchorListStickyConfig<ChatRow>[]>(
  () => [
    // Список уходит под навбар — эту высоту знает только вызывающий.
    { edge: "start", indices: dayIndices, offset: navbarHeight },
    // Отступ не задан: подставится `insetEnd`.
    { edge: "end", indices: avatarIndices, mode: "offset" },
  ],
  [dayIndices, avatarIndices, navbarHeight],
);
```

## Верхний отступ

Навбар над списком — это просто раскладка снаружи: `AnchorList` с `flex: 1` под
навбаром. Списку про верхний отступ знать не нужно.

Он нужен только прилипанию: `sticky[].offset` для `edge: "start"` — это высота
навбара, если список уходит под него.

## Частые ошибки

| Симптом | Причина |
| --- | --- |
| Последняя строка под панелью ввода | Нет распорки в `ListFooterComponent` |
| Отступ растёт, а контент стоит | Есть распорка, но нет сдвига скролла: она добавляется в конец и видимые строки не двигает |
| Компенсация не работает только у самого низа | Место не зарезервировано заранее — сдвиг упёрся в ещё не выросший диапазон |
| Контент прыгает в конце закрытия | Резерв держит открытое значение всю анимацию: он должен считаться от целевой высоты, а не копиться |
| Кнопка «вниз» уезжает раньше клавиатуры или виснет наверху | Взята высота распорки вместо живого перекрытия |
| Компенсация дерётся с пальцем | Не подключены `onScrollBeginDrag` / `onScrollEndDrag` |
| Индикатор скролла доходит до низа экрана | Не передан `insetEnd` |
| На iOS индикатор кончается слишком высоко | Safe area посчитана дважды: она уже входит в `insetEnd` |
| Между строкой ввода и клавишами пустая полоса | Безопасная зона не гасится по мере перекрытия клавиатурой |

## Проверить руками

Стенд «Нижний отступ» в [`example/`](../example): компенсация отключается
тумблером — видно, как контент уходит под панель без неё. Отдельно стоит
проверить самый низ списка: именно там ломается компенсация без резерва места.
