# Отступы и клавиатура

Внизу экрана переписки лежат панель ввода, безопасная зона и клавиатура. Список
должен заканчиваться над ними, подниматься вместе с клавиатурой, и то же самое
должны делать индикатор скролла и прилипший к нижней кромке якорь. Всё это
список считает от одного значения — `insetEnd`.

```
┌─────────────────┐
│    навбар       │
├─────────────────┤
│                 │
│    сообщения    │  ← контент кончается здесь
│                 │
├─────────────────┤
│  панель ввода   │
├─────────────────┤
│                 │
│   клавиатура    │
│                 │
└─────────────────┘
```

## Включение

```tsx
<AnchorList insetEnd={contentInset} ... />
```

`insetEnd` — shared value с высотой всего, что перекрывает список снизу: панель
ввода плюс клавиатура или безопасная зона. От него список сам:

- ставит распорку в конце контента, чтобы последняя строка останавливалась над
  панелью, а `scrollToEnd` и прилипание к концу считались без поправок;
- поднимает смещение скролла вместе с клавиатурой, когда контента больше
  экрана;
- вычитает отступ из [`alignItemsAtEnd`](scrolling.md#alignitemsatend), когда
  контента меньше экрана;
- отодвигает индикатор скролла;
- отодвигает прилипший якорь конечной кромки.

Всё это считается на UI-потоке и едет с клавиатурой в один кадр. Значение,
посчитанное в JS и приходящее рендером, отстаёт на кадр и больше — так делать
не нужно.

Пока палец на экране или идёт инерция, позицией управляет жест, и список её не
трогает.

## Как посчитать `insetEnd`

Перекрытие снизу — это **максимум** из клавиатуры и безопасной зоны, а не их
сумма: открытая клавиатура сама закрывает домашний индикатор. К перекрытию
добавляется высота панели ввода:

```tsx
/** Перекрытие: клавиатура либо безопасная зона. */
const occludedBottom = useDerivedValue(() =>
  Math.max(keyboardHeight.value, safeAreaBottom),
);

/** Полное перекрытие: зона плюс панель ввода. */
const contentInset = useDerivedValue(
  () => occludedBottom.value + barHeight.value,
);
```

Готовые хуки лежат в примере:
[`useKeyboardHeight`](../example/src/ui/useKeyboardHeight.ts) отдаёт высоту
клавиатуры покадрово, [`useKeyboardInset`](../example/src/ui/useKeyboardInset.ts)
считает перекрытие и умеет замораживать его на закрытом положении — тогда
список о клавиатуре не знает и раскладку не трогает.

### Откуда брать высоту клавиатуры

Требование одно: shared value, которая меняется на UI-потоке покадрово.

`react-native-keyboard-controller` отдаёт положение на каждом кадре, включая
закрытие свайпом, а в `onStart` — длительность анимации:

```tsx
import { useKeyboardHandler } from "react-native-keyboard-controller";

useKeyboardHandler({
  onStart: event => {
    "worklet";

    // Покадровые события приходят не на всех платформах: без анимации
    // движение было бы ступенчатым.
    height.value = withTiming(event.height, { duration: event.duration });
  },
  onMove: event => {
    "worklet";

    height.value = event.height;
  },
  // Закрытие свайпом по списку: высота идёт за пальцем.
  onInteractive: event => {
    "worklet";

    height.value = event.height;
  },
  onEnd: event => {
    "worklet";

    height.value = event.height;
  },
});
```

Приложение оборачивается в `KeyboardProvider`.

`Keyboard.addListener` из React Native даёт высоту только в момент показа, без
длительности и без закрытия свайпом. Для плавного движения его недостаточно.

## Панель ввода

Панель поднимается трансформом на высоту клавиатуры, а её нижний отступ под
безопасную зону гасится по мере того, как клавиатура эту зону перекрывает:

```tsx
const composerStyle = useAnimatedStyle(() => ({
  paddingBottom: occludedBottom.value - keyboardHeight.value,
  transform: [{ translateY: -keyboardHeight.value }],
}));
```

Полный след панели от низа экрана — `occludedBottom + barHeight`, то есть тот
самый `contentInset`, который уходит в `insetEnd`.

Кнопка «вниз» берёт то же перекрытие — рецепт в
[Рецептах](recipes.md#кнопка-вниз).

## Прилипание и отступы

Отступ конечной кромки для `sticky` подставляется из `insetEnd` сам. Задавать
его вручную нужно только у начальной кромки, где список уходит под навбар:

```tsx
const sticky = useMemo<IAnchorListStickyConfig<ChatRow>[]>(
  () => [
    // Высоту навбара знает только вызывающий.
    { edge: "start", indices: dayIndices, offset: navbarHeight },
    // Отступ не задан: подставится `insetEnd`.
    { edge: "end", indices: avatarIndices, mode: "offset" },
  ],
  [dayIndices, avatarIndices, navbarHeight],
);
```

## Верхний отступ

Навбар над списком — обычная раскладка снаружи: `AnchorList` с `flex: 1` под
навбаром. Самому списку верхний отступ не нужен, он нужен только прилипанию,
через `sticky[].offset` для `edge: "start"`.

## Частые ошибки

| Симптом | Причина |
| --- | --- |
| Последняя строка под панелью ввода | Не передан `insetEnd` |
| Двойной отступ снизу, короткий список прокручивается | Распорка осталась в `ListFooterComponent` |
| Контент дёргается вместо движения с клавиатурой | Значение считается в JS и приходит рендером |
| Кнопка «вниз» уезжает раньше клавиатуры | Взята не та величина: нужно живое перекрытие |
| Индикатор скролла доходит до низа экрана | Не передан `insetEnd` |
| На iOS индикатор кончается слишком высоко | Safe area посчитана дважды: она уже входит в `insetEnd` |
| Между строкой ввода и клавишами пустая полоса | Безопасная зона не гасится по мере перекрытия |
