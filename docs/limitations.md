# Ограничения

Здесь всё, чего `AnchorList` не делает.

## Чего нет

| Возможность | Состояние | Почему |
| --- | --- | --- |
| Горизонтальные списки | Нет | Вся геометрия — ось скролла, кромки, прилипание, распорки — написана под вертикаль. Обобщение затронуло бы каждый расчёт |
| Несколько колонок, masonry | Нет | Раскладка одномерная: позиция элемента — префиксная сумма высот предыдущих |
| `inverted` | Нет, и не планирую | Исходная задача решается прямо — см. [Миграция](migration.md#что-делать-вместо-inverted) |
| `RefreshControl` / pull-to-refresh | Нет | Требует доступа к `ScrollView` изнутри; пока можно через `refScrollView` — но своей поддержки нет |
| Секции (`SectionList`) | Нет | Данные — плоский массив. Секции строятся снаружи, прилипание заголовков — через `sticky` |
| Свайп по строке | Нет | Дело ячейки, а не списка |
| Перетаскивание строк | Нет | — |
| `flashScrollIndicators` | Нет | — |
| Анимации вставки и удаления строк | Нет | Позиции считаются напрямую; промежуточные состояния раскладки не моделируются |

## Обязательные условия

**Reanimated 4+ и `react-native-worklets`.** Смещение скролла обязано попадать в
shared value синхронно с нативным скроллом. Заменить это нечем —
см. [Установка](installation.md#почему-reanimated-обязателен).

**Стабильные уникальные ключи.** На ключе держатся измеренные размеры, привязка
контейнеров и якоря удержания позиции. Дубликаты не допускаются, ключ от индекса
зависеть не должен.

**`estimatedItemSize`.** Без стартовой оценки раскладке не с чего начать.

**Явная высота списка.** `flex: 1` или конкретное число.

## Поведение, о котором стоит знать заранее

**`ItemSeparatorComponent` входит в высоту ячейки.** Он рисуется внутри строки, а
не между строками. Объявленные через `getFixedItemSize` размеры обязаны его
учитывать. В `FlatList` это устроено иначе.

**`bounces` выключен.** Список задаёт `bounces={false}` нативному `ScrollView` и
не даёт это изменить: пружина у кромки расходится с расчётом расстояний до неё.

**Клавиатура закрывается свайпом по списку.** Список задаёт нативному
`ScrollView` `keyboardDismissMode`: `interactive` на iOS, `on-drag` на Android —
и не даёт это изменить. Интерактивное закрытие идёт покадрово вместе с пальцем, а
нижний отступ приходит тем же кадром, поэтому контент едет за клавиатурой без
рывка.

**Отдельного `onScroll` нет.** Смещение отдаётся через
`sharedValues.scrollOffset`. Событие на каждый кадр, проходящее через JS, — ровно
та цена, которой список и старается избежать.

**Объявленный размер необратим.** Размер, заданный через `getFixedItemSize`,
живёт в метриках и обратно в оценочный не превращается. Перевести список с
объявленных размеров на измеряемые можно только пересозданием (сменой `key`).

**Среднее по типу фиксируется.** После 32 замеров оценка
неизмеренных строк перестаёт меняться. Если строки одного типа сильно разной
высоты, оценка так и останется усреднённой — лучше развести их по типам.

**Пачка появившихся элементов ограничена.** Если разом появилось больше 32 новых
элементов, они идут по среднему, без ожидания измерения: смонтировать разом
страницу истории ради измерения дороже, чем полоса на один кадр.

**Первый показ имеет конечную страховку.** Без стартовой позиции и без новых
замеров список покажется через 150 мс как есть. Пока раскладка продолжает
меняться или заданная стартовая позиция ещё не устаканилась, страховка ждёт до
десяти дополнительных кругов. Это ограничивает ожидание примерно 1,65 секунды:
дальше список показывается на той позиции, до которой дошёл.

### Web требует доработок

Собирается, но не работает. Я проверил ровно одно, и то руками: бандл примера
собирается. В браузере список я не запускал.

Главное, что мешает, — удержание видимой позиции. Сдвиг выполняет нативный
`ScrollView` через `maintainVisibleContentPosition`, а `react-native-web` этого
свойства не реализует: механики, ради которой я всё и писал, на web просто нет.
Чтобы она заработала в браузере, компенсацию придётся написать заново.

Пока считайте web неподдержанным: issue про поведение в браузере я закрою, а вот
про саму поддержку — заводите.

## Что может появиться

Сроков не назову, но сделать хочу:

- pull-to-refresh;
- анимации вставки и удаления;
- горизонтальная ось.

Многоколоночную раскладку и `inverted` делать не буду: первая требует переписать
геометрию, а вторую задачу я решил иначе.
