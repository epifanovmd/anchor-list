# Ограничения

Чего `AnchorList` не делает, что требует и в чём отличается от `FlatList`.

## Чего нет

| Возможность | Причина |
| --- | --- |
| Несколько колонок, masonry | Раскладка одномерная: позиция элемента — сумма размеров предыдущих |
| `inverted` | Та же задача решается прямым списком — см. [Миграцию](migration.md#что-делать-вместо-inverted) |
| `RefreshControl` / pull-to-refresh | Своей поддержки нет; до `ScrollView` можно дотянуться через `refScrollView` |
| Секции (`SectionList`) | Данные — плоский массив; прилипающие заголовки делаются через `sticky` |
| Горизонтальный список под RTL | Нативное удержание позиции не учитывает RTL — см. ниже |
| Web | Удержание позиции опирается на нативный `maintainVisibleContentPosition`, которого нет в `react-native-web` |
| Анимации вставки и удаления строк | — |
| Перетаскивание строк, свайп по строке | Дело ячейки, а не списка |
| `flashScrollIndicators` | — |

## Обязательные условия

- **Новая архитектура, React Native 0.78+, React 19+, Reanimated 4+.** См.
  [Установку](installation.md#зависимости).
- **Стабильные уникальные ключи.** Ключ не зависит от индекса и не меняется у
  того же элемента.
- **`estimatedItemSize`.** Без стартовой оценки список не откроется.
- **Явный размер списка.** `flex: 1` или конкретное число. У горизонтального
  списка обязательна и высота: строка растянута на неё, без неё лента
  схлопывается.

## Особенности поведения

**`ItemSeparatorComponent` входит в высоту ячейки.** Он рисуется внутри строки,
а не между строками; объявленные через `getFixedItemSize` размеры обязаны его
учитывать. В `FlatList` устроено иначе.

**Отдельного `onScroll` нет.** Смещение отдаётся через
`sharedValues.scrollOffset` на UI-потоке.

**`bounces` выключен** и не настраивается.

**`keyboardDismissMode` задаёт список**: `interactive` на iOS, `on-drag` на
Android.

**`horizontal` + RTL не поддерживается.** Под RTL нативный слой отсчитывает
горизонтальное смещение от правой кромки, а нативное удержание позиции на
Android этого не учитывает и компенсирует в противоположную сторону. Со стороны
списка это не чинится; в DEV он один раз предупреждает в консоль. Вертикальных
списков ограничение не касается.

**Объявленный размер необратим.** Размер из `getFixedItemSize` обратно в
измеряемый не превращается: перевести список с объявленных размеров на
измеряемые можно только пересозданием (сменой `key`).

**Среднее по типу фиксируется после 32 замеров.** Строки одного типа с сильно
разной высотой разводите по разным типам.

**Пачка появившихся элементов ограничена 32 строками.** Если разом появилось
больше, они встают по среднему, без ожидания измерения.

**Первый показ ограничен по времени.** Если замеры не приходят, список
показывается по страховке: 150 мс, и до десяти дополнительных кругов, пока
раскладка меняется.
