# Удержание видимой позиции

Когда над видимой частью списка что-то меняется — подгрузилась история,
докачалась картинка и строка выросла, — всё, что на экране, уезжает вниз.
Эта механика возвращает видимую строку на то же место экрана, где она была до
изменения. Пользователь ничего не замечает.

## Включение

```tsx
<AnchorList
  maintainVisibleContentPosition={{ data: true, size: true }}
  ...
/>
```

| Поле | По умолчанию | Что компенсирует |
| --- | --- | --- |
| `data` | `false` | Вставку и удаление элементов выше вьюпорта |
| `size` | `false` | Изменение размера уже отрисованных строк выше вьюпорта |
| `shouldRestorePosition` | — | Свой выбор строки, которую держать |

Две причины независимы. Ленте, которая растёт только вниз, не нужна ни одна.
Переписке с подгрузкой истории нужны обе.

Объект сравнивается по ссылке, поэтому его нужно мемоизировать:

```tsx
const maintainVisibleContentPosition = useMemo(
  () => ({ data: true, size: true }),
  [],
);
```

## Что происходит

Перед изменением список запоминает строку, которая стоит у верхней кромки.
После изменения он находит ту же строку по ключу, смотрит, на сколько уехала её
позиция, и на столько же сдвигает скролл. Сдвиг делает нативный `ScrollView` в
той же транзакции, что и раскладка, поэтому жест и инерция не прерываются, а
рывка между кадрами нет.

Строкой-опорой становится первая строка, целиком лежащая ниже верхней кромки.
Если таких нет, берётся строка, торчащая над кромкой. Неизмеренные строки не
годятся. На случай, если опора исчезнет вместе с изменением, список запоминает
ещё несколько строк ниже неё.

Как это сделано внутри — [Механика](mechanics.md#5-удержание-позиции).

## Что стоит знать

**Компенсация по размерам не работает на быстром броске.** Если список идёт
быстрее примерно трёх сотых экрана в миллисекунду, замер выросшей строки
применяется без сдвига: на такой скорости рывок не виден, а сдвиг был бы
дороже. Решение принимается в момент, когда строка меняет размер: если список в
этот момент шёл спокойно, сдвиг доводится до конца, даже если потом он
разогнался. Компенсация по данным работает на любой скорости.

**Работает только выше вьюпорта.** Изменения ниже видимой части ничего не
двигают: их и так не видно.

**Нужны стабильные ключи.** Опора адресуется ключом. Если ключ меняется вместе
с элементом, после изменения опору не найти, и в замере растёт `без якоря`.

**Сдвиг упирается в границу скролла.** Если контент короче вьюпорта или
скролл стоит на самой границе, часть сдвига применить некуда. В замере это
`упор` и `потеряно`.

**Пока идёт стартовая позиция, компенсация выключена.** До первого показа
списком распоряжается только [начальный скролл](scrolling.md#стартовая-позиция).

## `shouldRestorePosition`

Позволяет исключить строки, которые не годятся в опору. Типичный случай —
спиннер подгрузки: он исчезает тем же изменением, ради которого опора и
снималась.

```tsx
maintainVisibleContentPosition={{
  data: true,
  size: true,
  shouldRestorePosition: item => item.type === "message",
}}
```

Функция вызывается для каждого кандидата сверху вниз; возврат `false` исключает
элемент.

## Что видно в замере

Когда механика работает, во встроенном замере
([Производительность](performance.md#встроенный-замер)) появляется строка
`mvcp`:

```
  mvcp      12 захватов · 12 восстановлений (данные 8 / размер 4) · на броске пропущено 0 · второй проход 3 · сдвиг 340/1204px
            упор 0 · потеряно 0/0px · без якоря 0 · запасной якорь 2 · промах 0 на 0/0px
```

| Величина | Что значит |
| --- | --- |
| `захватов` / `восстановлений` | Сколько раз опора снималась и применялась |
| `данные` / `размер` | По какой из двух причин |
| `на броске пропущено` | Замеров, не снявших опору по скорости |
| `второй проход` | Сдвиг разошёлся с предсказанным, раскладка посчитана заново |
| `сдвиг` | Средний и максимальный сдвиг, px |
| `упор` | Сдвиг упёрся в границу скролла |
| `потеряно` | Сколько пикселей сдвига не применилось |
| `без якоря` | Ни один кандидат не подошёл |
| `запасной якорь` | Первый кандидат не пережил изменение, взят следующий |
| `промах` | Позиция после восстановления разошлась с ожидаемой |

`упор`, `без якоря` и `промах` в норме нулевые. Если нет —
[Симптомы](troubleshooting.md#контент-прыгает-при-подгрузке-сверху).
