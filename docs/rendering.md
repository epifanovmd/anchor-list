# Отрисовка строк

## Что приходит в `renderItem`

```ts
interface IAnchorListRenderItemProps<TItem> {
  item: TItem;
  index: number;
  type: string;
  extraData: unknown;
  stickyOffset?: SharedValue<number>;
  stickyPinned?: SharedValue<boolean>;
}
```

```tsx
const renderItem = useCallback(
  ({ item, index }: IAnchorListRenderItemProps<IMessage>) => (
    <MessageRow message={item} isFirst={index === 0} />
  ),
  [],
);
```

`index` — индекс в **текущих** данных. После подгрузки страницы сверху у того же
сообщения он другой. Всё, что должно пережить смену данных, адресуется ключом.

## Ключи

Ключ — адрес элемента внутри списка. На нём держатся:

- измеренные размеры (иначе каждая вставка сверху обнуляла бы все измерения);
- привязка контейнеров к элементам;
- якоря удержания видимой позиции;
- `scrollToKey` и `getPositionByKey`.

Требования:

- **постоянный для элемента** — не зависит от индекса и от порядка;
- **уникальный** — два элемента с одним ключом список не допускает.

```tsx
keyExtractor={message => message.id}                        // да
keyExtractor={row => `${row.type}:${row.id}`}               // да, если id уникален внутри типа
keyExtractor={(_, index) => String(index)}                  // нет
keyExtractor={message => `${message.id}:${message.status}`} // нет: ключ меняется у того же элемента
```

Последний случай коварен: при смене статуса сообщение выглядит для списка как
исчезновение одного элемента и появление другого. Измеренная высота теряется,
удержание позиции остаётся без якоря.

## Типы контейнеров

`getItemType` говорит списку, какие строки взаимозаменяемы.

```tsx
getItemType={row => {
  if (row.type !== "message") return row.type;

  return row.hasAttachment ? "message-media" : "message-text";
}}
```

Тип влияет на две вещи:

**1. Переработку контейнеров.** Свободный контейнер того же типа предпочитается
любому другому: попадание по типу означает совпадающую структуру поддерева, и
React меняет пропы вместо перемонтирования.

**2. Оценку неизмеренных строк.** Средний замеренный размер копится отдельно по
каждому типу. Разделитель дат высотой 44 не должен портить оценку сообщений
высотой 92.

Среднее по типу набирается по 32 замерам и **фиксируется**.
После этого точнее оно уже не станет, а меняться не перестаёт: каждое изменение
переставляет разом все неизмеренные строки — суммарная высота контента гуляет на
сотни пикселей, отведённое строке место расходится с тем, чем она нарисована, и
между строками то появляется, то пропадает пустая полоса.

## Размеры

У списка три источника размера строки, в порядке приоритета:

| Источник | Когда используется |
| --- | --- |
| `getFixedItemSize` | Размер объявлен — измерение пропускается совсем |
| Измеренная высота | Строка была смонтирована и измерена через `onLayout` |
| Оценка | Средний замер по типу; до первых замеров — `estimatedItemSize` |

### Объявленные размеры

```tsx
const rowHeight = (row: ChatRow): number | undefined => {
  if (row.type === "day") return 44;
  if (row.type === "spinner") return 56;

  return undefined; // сообщение — измеряем
};

<AnchorList getFixedItemSize={rowHeight} estimatedItemSize={92} />;
```

Возврат `undefined` означает «неизвестно, измеряй». Так можно объявить размеры
служебных строк и оставить измерение содержательным.

Объявленный размер живёт в метриках и обратно в оценочный не превращается. Если
нужно перевести список с объявленных размеров на измеряемые — пересоздайте его
сменой `key`:

```tsx
<AnchorList key={knownHeights ? "fixed" : "measured"} ... />
```

### Измерение

Строка без объявленного размера измеряется при монтировании. Пока она не
измерена, ей отводится оценочная высота.

Два следствия:

- **Появившийся элемент не занимает места, пока его не измерили.** Иначе на кадр
  вставки разошлись бы отведённый слот и нарисованная высота. Такая строка
  уводится выше начала контента — туда скролл не доходит, а раскладка идёт своим
  чередом.
- **Пачка появившихся элементов ограничена.** Если разом появилось больше 32
  новых элементов (подгруженная страница истории), они идут по среднему, без
  ожидания измерения: смонтировать разом страницу ради измерения дороже, чем
  полоса на один кадр.

Изменения измеренной высоты меньше порога считаются шумом округления экрана и
раскладку не двигают.

### До первого показа

До измерений позиции оценочные, и строки с непохожей высотой налезают друг на
друга. Показывать такой кадр нельзя — он и есть та самая каша при открытии.

Список раскрывается, когда:

- видимые строки измерены, **или**
- их размеры объявлены пропом и измерять нечего, **или**
- прошло 150 мс — страховка на случай, когда измерений не будет вовсе (пустые
  данные, нулевая высота ячейки).

При заданном `initialScroll` показом распоряжается начальный скролл: там ждать
нужно не измерений, а того, что цель перестала уезжать.

## Переработка контейнеров

```tsx
<AnchorList recycleItems getItemType={row => row.type} />
```

Контейнер — единица монтирования. Строк в данных тысячи, а смонтированных
контейнеров — по числу тех, что помещаются в диапазон отрисовки. Контейнер
переживает смену элемента: ядро меняет его сигналы, и перерисовывается только он.

### Состояние внутри ячейки

> [!WARNING]
> **`useState` внутри перерабатываемой строки достаётся чужому элементу.**
> Обычный `useState` живёт вместе с **контейнером**, а контейнер при
> `recycleItems` переживает смену элемента: поддерево не перемонтируется, React
> лишь меняет пропы. Развёрнутый текст, начатое проигрывание, снятая отметка,
> позиция карусели — всё это остаётся от предыдущей строки и достаётся той,
> которая заняла тот же контейнер. Выглядит как «пролистнул — развернулось
> совсем другое сообщение», и воспроизводится только на списке длиннее диапазона
> отрисовки, поэтому до продакшена доживает легко.

Правильных ответов два, и выбирают между ними не по вкусу, а по тому, обязано ли
состояние пережить уход строки за пределы диапазона.

**Состояние живёт, пока строка на экране** — `useAnchorListItemState`. Он
адресован ключом элемента: сменился ключ — значение вернулось к начальному, и
сделано это прямо в рендере, до коммита. Кадра с чужим состоянием не бывает, а
это важно вдвойне: этим же кадром список измеряет строку, и иначе в метрики
ушла бы чужая высота.

```tsx
import { useAnchorListItemState } from "@epifanovmd/anchor-list";

const Row = ({ item }) => {
  // сбрасывается сам, когда контейнер возьмёт другой элемент
  const [expanded, setExpanded] = useAnchorListItemState(false);

  return <Pressable onPress={() => setExpanded(v => !v)}>{/* ... */}</Pressable>;
};
```

Начальное значение можно вычислить от элемента — при смене элемента оно
пересчитается уже по новому:

```tsx
const [expanded, setExpanded] = useAnchorListItemState(() => item.expandedByDefault);
```

Вызывать хук нужно **внутри компонента, который вернул `renderItem`**, а не в
теле самого `renderItem`: там он привязался бы к контейнеру, то есть ровно к
тому, от чего защищает. Такой вызов падает с объясняющей ошибкой, а не молча.

**Состояние обязано пережить возврат к строке** — внешний стор по ключу
элемента. Тут переработка ни при чём: строка, ушедшая дальше `drawDistance`,
размонтируется в любом виртуализированном списке, и с ней уходит всё локальное.
Ключ приходит в `renderItem` полем `itemKey` — тот же, что вернул
`keyExtractor`:

```tsx
const renderItem = useCallback(
  ({ item, itemKey }) => (
    <Row
      item={item}
      expanded={expandedIds.has(itemKey)}
      onToggle={() => toggle(itemKey)}
    />
  ),
  [expandedIds, toggle],
);
```

Прилипающие контейнеры живут отдельно от обычных: их держат смонтированными и за
пределами видимого диапазона, поэтому под обычные элементы они не уходят. Кроме
того, у прилипающей и обычной строки разная React/Reanimated-структура, и
контейнеры между этими двумя ролями не переиспользуются.

## Пропуск повторных рендеров

По умолчанию элементы сравниваются по ссылке: новый объект с теми же полями
перерисует строку. Если данные пересобираются целиком на каждом обновлении —
скажите, что считать одинаковым:

```tsx
const itemsAreEqual = useCallback(
  (prev: IMessage, next: IMessage) =>
    prev.id === next.id &&
    prev.text === next.text &&
    prev.status === next.status,
  [],
);

<AnchorList itemsAreEqual={itemsAreEqual} />;
```

## Слоты

### Шапка и подвал

```tsx
<AnchorList
  ListHeaderComponent={<ChannelHeader channel={channel} />}
  ListFooterComponent={<TypingIndicator chatId={chatId} />}
/>
```

Принимаются и элементом, и типом компонента. Высоты обоих измеряются и входят в
полную высоту контента.

### Пустое состояние

```tsx
<AnchorList ListEmptyComponent={<EmptyChat />} />
```

Показывается вместо элементов, когда `data` пуст. Шапка и подвал остаются.

### Разделитель

```tsx
<AnchorList ItemSeparatorComponent={Divider} />
```

Разделитель рисуется **внутри** ячейки, под содержимым строки, и входит в её
высоту. Это отличается от `FlatList`, где он отдельный узел между ячейками.

Практическое следствие: если для строки объявлен `getFixedItemSize`, объявленная
высота обязана включать разделитель.
