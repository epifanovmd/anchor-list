# Отрисовка строк

## Что приходит в `renderItem`

```ts
interface IAnchorListRenderItemProps<TItem> {
  item: TItem;
  index: number;
  itemKey: string;
  type: string;
  extraData: unknown;
  stickyOffset?: SharedValue<number>;
  stickyPinned?: SharedValue<boolean>;
}
```

```tsx
const renderItem = useCallback(
  ({ item, index }: IAnchorListRenderItemProps<IMessage>) => (
    <MessageRow message={item} isFirst={index === 0} />
  ),
  [],
);
```

`index` — индекс в **текущих** данных: после подгрузки страницы сверху у того же
сообщения он другой. Всё, что должно пережить смену данных, адресуется ключом
(`itemKey`).

## Ключи

На ключе держатся:

- измеренные размеры;
- привязка контейнеров к элементам;
- якоря удержания видимой позиции;
- `scrollToKey` и `getPositionByKey`.

Требования: постоянный для элемента, не зависит от индекса и порядка,
уникальный.

```tsx
keyExtractor={message => message.id}                        // да
keyExtractor={row => `${row.type}:${row.id}`}               // да, если id уникален внутри типа
keyExtractor={(_, index) => String(index)}                  // нет
keyExtractor={message => `${message.id}:${message.status}`} // нет: ключ меняется у того же элемента
```

Ключ, меняющийся вместе с элементом, для списка означает исчезновение одного
элемента и появление другого: измеренная высота теряется, удержание позиции
остаётся без якоря.

## Типы контейнеров

`getItemType` говорит, какие строки взаимозаменяемы.

```tsx
getItemType={row => {
  if (row.type !== "message") return row.type;

  return row.hasAttachment ? "message-media" : "message-text";
}}
```

Тип влияет на две вещи:

1. **Переработку контейнеров.** Свободный контейнер того же типа предпочитается
   любому другому.
2. **Оценку неизмеренных строк.** Средний замеренный размер копится отдельно по
   каждому типу.

Оценка, однажды выданная строке, задним числом не меняется. Исключение —
догадка из `estimatedItemSize`, выданная до первых замеров типа: первый замер
типа заменяет её накопленным средним.

Среднее по типу набирается по 32 замерам и **фиксируется**.

## Размеры

Три источника размера строки, в порядке приоритета:

| Источник | Когда используется |
| --- | --- |
| `getFixedItemSize` | Размер объявлен — измерение пропускается |
| Измеренная высота | Строка была смонтирована и измерена через `onLayout` |
| Оценка | Средний замер по типу; до первых замеров — `estimatedItemSize` |

### Объявленные размеры

```tsx
const rowHeight = (row: ChatRow): number | undefined => {
  if (row.type === "day") return 44;
  if (row.type === "spinner") return 56;

  return undefined; // сообщение — измеряем
};

<AnchorList getFixedItemSize={rowHeight} estimatedItemSize={92} />;
```

Возврат `undefined` означает «неизвестно, измеряй».

Объявленный размер обратно в оценочный не превращается. Перевести список с
объявленных размеров на измеряемые можно только сменой `key`:

```tsx
<AnchorList key={knownHeights ? "fixed" : "measured"} ... />
```

### Измерение

Строка без объявленного размера измеряется при монтировании; до измерения ей
отводится оценочная высота.

- **Появившийся элемент не занимает места, пока не измерен.** Такая строка
  уводится выше начала контента, куда скролл не доходит.
- **Пачка появившихся элементов ограничена 32 строками.** Больше — идут по
  среднему, без ожидания измерения.
- **Изменения измеренной высоты меньше порога** считаются шумом округления
  экрана и раскладку не двигают.

### До первого показа

Список раскрывается, когда:

- видимые строки измерены, **или**
- их размеры объявлены пропом, **или**
- прошёл тихий круг страховки в 150 мс (до десяти дополнительных кругов, пока
  замеры продолжаются).

При заданном `initialScroll` показом распоряжается
[начальный скролл](scrolling.md#стартовая-позиция).

## Переработка контейнеров

```tsx
<AnchorList recycleItems getItemType={row => row.type} />
```

Контейнер переживает смену элемента: ядро меняет его сигналы, перерисовывается
только он.

### Состояние внутри ячейки

> [!WARNING]
> **`useState` внутри перерабатываемой строки достаётся чужому элементу.** Он
> живёт вместе с контейнером, а контейнер при `recycleItems` меняет элементы под
> собой: развёрнутый текст, начатое проигрывание, снятая отметка, позиция
> карусели остаются от предыдущей строки.

Выбор из двух зависит от того, обязано ли состояние пережить уход строки за
пределы диапазона отрисовки.

**Состояние живёт, пока строка на экране** — `useAnchorListItemState`. Он
адресован ключом элемента и сбрасывается при смене ключа прямо в рендере, до
коммита.

```tsx
import { useAnchorListItemState } from "@epifanovmd/anchor-list";

const Row = ({ item }) => {
  // сбрасывается сам, когда контейнер возьмёт другой элемент
  const [expanded, setExpanded] = useAnchorListItemState(false);

  return <Pressable onPress={() => setExpanded(v => !v)}>{/* ... */}</Pressable>;
};
```

Начальное значение можно вычислить от элемента — при смене элемента оно
пересчитается:

```tsx
const [expanded, setExpanded] = useAnchorListItemState(() => item.expandedByDefault);
```

Вызывать хук нужно **внутри компонента, который вернул `renderItem`**, а не в теле
самого `renderItem`. Такой вызов падает с объясняющей ошибкой.

**Состояние обязано пережить возврат к строке** — внешний стор по ключу
элемента. Ключ приходит в `renderItem` полем `itemKey`:

```tsx
const renderItem = useCallback(
  ({ item, itemKey }) => (
    <Row
      item={item}
      expanded={expandedIds.has(itemKey)}
      onToggle={() => toggle(itemKey)}
    />
  ),
  [expandedIds, toggle],
);
```

Прилипающие контейнеры живут отдельно от обычных и между этими ролями не
переиспользуются.

## Пропуск повторных рендеров

По умолчанию элементы сравниваются по ссылке. Если данные пересобираются целиком,
задайте своё сравнение:

```tsx
const itemsAreEqual = useCallback(
  (prev: IMessage, next: IMessage) =>
    prev.id === next.id &&
    prev.text === next.text &&
    prev.status === next.status,
  [],
);

<AnchorList itemsAreEqual={itemsAreEqual} />;
```

## Слоты

### Шапка и подвал

```tsx
<AnchorList
  ListHeaderComponent={<ChannelHeader channel={channel} />}
  ListFooterComponent={<TypingIndicator chatId={chatId} />}
/>
```

Принимаются элементом и типом компонента. Высоты обоих измеряются и входят в
полную высоту контента.

### Пустое состояние

```tsx
<AnchorList ListEmptyComponent={<EmptyChat />} />
```

Показывается вместо элементов, когда `data` пуст. Шапка и подвал остаются.

### Разделитель

```tsx
<AnchorList ItemSeparatorComponent={Divider} />
```

Разделитель рисуется **внутри** ячейки, под содержимым строки, и входит в её
высоту — в `FlatList` это отдельный узел между ячейками. Объявленная через
`getFixedItemSize` высота обязана включать разделитель.
