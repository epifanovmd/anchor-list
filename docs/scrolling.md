# Скролл и позиционирование

## Стартовая позиция

```tsx
<AnchorList initialScroll={{ type: "end" }} ... />
```

```ts
type AnchorListInitialScroll =
  | { type: "end" }
  | { type: "offset"; offset: number }
  | { type: "index"; index: number; viewPosition?: number; viewOffset?: number };
```

| Вариант | Куда открывается |
| --- | --- |
| `{ type: "end" }` | Конец **контента** — вместе с подвалом и распорками |
| `{ type: "offset", offset }` | Прямое смещение в координатах контента |
| `{ type: "index", index, viewPosition, viewOffset }` | К элементу; `viewPosition` — куда прижать (0 к началу, 1 к концу, 0.5 по центру), `viewOffset` — поправка в px |

### До стартовой позиции список не показан

Цель считается по метрикам, а до измерения ячеек размеры оценочные, поэтому цель
уточняется от кадра к кадру. Позиция считается готовой, когда сошлось всё сразу:

- цель не изменилась между кадрами;
- замеры за этот кадр не приходили;
- строки, которые окажутся на экране, вместе с `drawDistance` измерены;
- список доехал до смещения, которое просила прошлая попытка.

После показа доводка не возвращается. Если измерения не приходят вовсе, показ
завершает страховка по времени.

Диагностика печатает по строке на попытку:

```ts
import { setAnchorListDebug } from "@epifanovmd/anchor-list";

setAnchorListDebug("initial");
```

Пока стартовый скролл активен, пороги кромок, удержание позиции, автоприлипание к
концу и нативная компенсация не вмешиваются: абсолютный offset задаёт только
доводка.

### Смещение просится целыми точками

Позиции строк дробные, нативный слой кладёт смещение на пиксель устройства.
Поэтому цель округляется до целой точки, а у конца контента — вниз.

Снимок позиции для восстановления хранить лучше как есть, без округления.

### `{ type: "end" }` — именно конец контента

Не конец элементов: под ними может лежать распорка под панель ввода.

### Цель ждёт замера контента

Стартовая позиция вычисляется после того, как `ScrollView` отдал замер высоты
контента. Попытки на более ранние кадры не тратятся.

### Восстановление позиции

Стартовая позиция задаётся **пропом**, а не методом ref: скролл нужен к первому
кадру.

```tsx
// Читается ровно один раз, до первого рендера.
const [saved] = useState(() => storage.read(SCREEN_ID));

const initialScroll = useMemo<AnchorListInitialScroll | undefined>(() => {
  if (!saved) return undefined;

  const index = data.findIndex(row => keyExtractor(row) === saved.key);

  if (index === -1) return undefined;

  return { type: "index", index, viewOffset: saved.offset };
}, [data, saved]);

<AnchorList initialScroll={initialScroll} ... />;
```

Хранилище должно быть **синхронным** (MMKV, а не AsyncStorage).

Сохранённое смещение берётся со знаком: отрицательное означает, что строка
уходит за кромку.

```tsx
const topIndex = list.getVisibleRange().start;
const position = list.getPositionAtIndex(topIndex);

storage.write({
  key: keyExtractor(data[topIndex]),
  offset: position - list.getScrollOffset(),
});
```

Полный рецепт — [Рецепты](recipes.md#восстановление-позиции).

## Программный скролл

Все четыре метода — в [Императивном API](imperative-api.md#скролл):
`scrollToIndex`, `scrollToKey`, `scrollToOffset`, `scrollToEnd`.

Пока идёт программный скролл, пороги кромок не проверяются. `scrollToEnd`
сохраняет цель до стабилизации высоты контента и доводит позицию повторно, если
измерения последних строк сдвинули конец. Жест пользователя отменяет доводку.

**Ключ надёжнее индекса:** после подгрузки сверху тот же элемент лежит на другом
индексе.

```tsx
// нет: индекс мог устареть между сохранением и переходом
listRef.current?.scrollToIndex({ index: savedIndex });

// да
const found = listRef.current?.scrollToKey({ key: savedKey });
if (!found) loadContextAround(savedKey);
```

## Прилипание к концу

```tsx
<AnchorList
  maintainScrollAtEnd={{ onlyWhenAtEnd: true, animated: true }}
  maintainScrollAtEndThreshold={0.1}
/>
```

| Поле | По умолчанию | Что делает |
| --- | --- | --- |
| `onlyWhenAtEnd` | `false` | Прилипать только если пользователь уже у конца |
| `animated` | `false` | Доводить позицию анимацией |

«У конца» определяется порогом `maintainScrollAtEndThreshold` (по умолчанию
`0.1` — десятая часть экрана). Это **отдельный** порог от порогов подгрузки.

### Поведение

- Скролл откладывается на следующий кадр: к этому моменту новый контент разложен
  и конец посчитан по фактическим размерам.
- Признак «пользователь был у конца» снимается **до** того, как контент вырос.
- Уведённый за отложенный кадр список отменяет прилипание. Сравнивается смещение;
  начало жеста отменяет прилипание отдельно.
- Повторные запросы во время прилипания копятся в один отложенный.

### Кнопка «вниз»

Тот же порог отдаётся сигналом:

```tsx
const isAtEnd = useSharedValue(true);

<AnchorList
  maintainScrollAtEnd={{ onlyWhenAtEnd: true, animated: true }}
  sharedValues={useMemo(
    () => ({ isWithinMaintainScrollAtEndThreshold: isAtEnd }),
    [isAtEnd],
  )}
/>;
```

## `alignItemsAtEnd`

```tsx
<AnchorList alignItemsAtEnd ... />
```

Прижимает контент к концу, пока его меньше экрана. Разницу добирает сдвиг слоя
контейнеров вниз: высота контента не меняется, короткий список остаётся
непрокручиваемым.

Место под панелью ввода из сдвига **вычитается** — его уже отдала распорка
[`insetEnd`](insets.md). Сдвиг считается на UI-потоке: пока контента меньше
экрана, именно он поднимает контент вместе с клавиатурой.

## `anchoredEndSpace`

Распорка у конца списка, растущая до якоря.

```tsx
<AnchorList
  anchoredEndSpace={{
    anchorIndex: quotedIndex,
    anchorOffset: 12,
    onSizeChanged: setSpaceSize,
  }}
/>
```

| Поле | Что делает |
| --- | --- |
| `anchorIndex` | Элемент, который должен доставать до верхней кромки |
| `anchorOffset` | Дополнительный отступ над якорем |
| `maxSize` | Верхняя граница размера распорки |
| `onSizeChanged` | Текущий размер; меняется вместе с раскладкой |

Размер:

```
размер = max(0, высота вьюпорта − контент под якорем − anchorOffset)
```

и не больше `maxSize`, если он задан.

Применение: переход к цитируемому сообщению у самого конца переписки, где под
целью не хватает контента на экран.

В отступ конца распорка входит, в расстояние до кромки для порогов подгрузки —
нет.

## `snapToIndices`

```tsx
<AnchorList snapToIndices={[0, 10, 20, 30]} />
```

Точки притяжения скролла. Индексы переводятся в смещения и уходят в
`snapToOffsets` нативного `ScrollView`. Смещения считаются на рендере, поэтому до
измерения строк они приблизительны — для точного снапа задавайте
`getFixedItemSize`.

## Что работает одновременно

| Механика | Работает вместе с |
| --- | --- |
| `initialScroll` | Всем: пока она активна, пороги и компенсация не вмешиваются |
| `maintainScrollAtEnd` | `maintainVisibleContentPosition` |
| `alignItemsAtEnd` | `maintainScrollAtEnd` |
| `anchoredEndSpace` | `scrollToKey` |
