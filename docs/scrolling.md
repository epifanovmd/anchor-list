# Скролл и позиционирование

## Стартовая позиция

```tsx
<AnchorList initialScroll={{ type: "end" }} ... />
```

```ts
type AnchorListInitialScroll =
  | { type: "end" }
  | { type: "offset"; offset: number }
  | { type: "index"; index: number; viewPosition?: number; viewOffset?: number };
```

| Вариант | Куда открывается |
| --- | --- |
| `{ type: "end" }` | Конец **контента** — вместе с подвалом и распорками |
| `{ type: "offset", offset }` | Прямое смещение в координатах контента |
| `{ type: "index", index, viewPosition, viewOffset }` | К элементу; `viewPosition` — куда прижать (0 к началу, 1 к концу, 0.5 по центру), `viewOffset` — поправка в px |

### До стартовой позиции список не показан

Иначе виден кадр, отрисованный по оценочным размерам, и доводка позиции на глазах
у пользователя.

Цель считается по метрикам, но до измерения ячеек размеры оценочные, поэтому
после каждого кадра измерений она уезжает. Скролл повторяется, пока все элементы
до цели не измерены — или пока не исчерпаны 10 попыток.

Пока стартовый скролл активен, пороги кромок не проверяются: иначе открытие
списка у конца сразу вызвало бы подгрузку.

### `{ type: "end" }` — именно конец контента

Не конец элементов. Под ними может лежать распорка под панель ввода, и по сумме
элементов список открылся бы с последней строкой под самой панелью.

Полная высота контента приходит замером `ScrollView` и на первом кадре ещё не
известна — цель уточнится на следующей попытке.

### Восстановление позиции

Стартовая позиция задаётся **пропом**, а не методом ref: скролл нужен к первому
кадру. Метод `scrollToIndex` после монтирования — это уже видимый прыжок.

```tsx
// Читается ровно один раз, до первого рендера.
const [saved] = useState(() => storage.read(SCREEN_ID));

const initialScroll = useMemo<AnchorListInitialScroll | undefined>(() => {
  if (!saved) return undefined;

  const index = data.findIndex(row => keyExtractor(row) === saved.key);

  if (index === -1) return undefined;

  return { type: "index", index, viewOffset: saved.offset };
}, [data, saved]);

<AnchorList initialScroll={initialScroll} ... />;
```

Хранилище должно быть **синхронным** (MMKV, а не AsyncStorage): после
асинхронного чтения список успеет открыться сверху и дёрнется.

Сохранённое смещение берётся со знаком — отрицательное означает, что строка
уходит за кромку, и именно оно возвращает её ровно тем же куском:

```tsx
const topIndex = list.getVisibleRange().start;
const position = list.getPositionAtIndex(topIndex);

storage.write({
  key: keyExtractor(data[topIndex]),
  offset: position - list.getScrollOffset(),
});
```

Полный рецепт — [Рецепты](recipes.md#восстановление-позиции).

## Программный скролл

Все четыре метода — в [Императивном API](imperative-api.md#скролл):
`scrollToIndex`, `scrollToKey`, `scrollToOffset`, `scrollToEnd`.

Пока идёт анимированный программный скролл, пороги кромок не проверяются.

**Ключ надёжнее индекса.** После подгрузки сверху тот же элемент лежит на другом
индексе:

```tsx
// нет: индекс мог устареть между сохранением и переходом
listRef.current?.scrollToIndex({ index: savedIndex });

// да
const found = listRef.current?.scrollToKey({ key: savedKey });
if (!found) loadContextAround(savedKey);
```

## Прилипание к концу

Новое сообщение обязано оказаться на экране само, без скролла руками.

```tsx
<AnchorList
  maintainScrollAtEnd={{ onlyWhenAtEnd: true, animated: true }}
  maintainScrollAtEndThreshold={0.1}
/>
```

| Поле | По умолчанию | Что делает |
| --- | --- | --- |
| `onlyWhenAtEnd` | `false` | Прилипать только если пользователь уже у конца |
| `animated` | `false` | Доводить позицию анимацией |

`onlyWhenAtEnd: true` — почти всегда то, что нужно: пользователь, ушедший читать
историю, не должен быть выдернут вниз новым сообщением.

«У конца» определяется порогом `maintainScrollAtEndThreshold` (по умолчанию `0.1`
— десятая часть экрана). Это **отдельный** порог от порогов подгрузки.

### Как это работает

- Скролл откладывается на следующий кадр: к этому моменту новый контент уже
  разложен, и конец списка посчитан по фактическим размерам, а не по оценкам.
- Решение «пользователь был у конца» снимается **до** того, как контент вырос.
  Добавленная снизу строка сама уводит список от конца, и по состоянию после неё
  «пользователь ушёл» от «внизу добавилось» уже не отличить — прилипание гасило
  бы само себя на любой строке выше порога.
- За отложенный кадр список могли увести — тогда прилипание отменяется, чтобы не
  выдёргивать ленту из-под пальца. Сравнивается смещение, а не флаг «у конца»:
  рост контента смещение не меняет, а флаг гасит. Начало жеста отменяет
  прилипание отдельно — во время анимированной доводки смещение двигает она сама,
  и по нему жест не отличить.
- Пока идёт одно прилипание, повторные запросы копятся в один отложенный: пачка
  сообщений не должна давать пачку конкурирующих скроллов.

### Кнопка «вниз»

Тот же порог отдаётся наружу сигналом:

```tsx
const isAtEnd = useSharedValue(true);

<AnchorList
  maintainScrollAtEnd={{ onlyWhenAtEnd: true, animated: true }}
  sharedValues={useMemo(
    () => ({ isWithinMaintainScrollAtEndThreshold: isAtEnd }),
    [isAtEnd],
  )}
/>;
```

Кнопка и прилипание тогда согласованы по определению: они смотрят на одно и то же
число.

## `alignItemsAtEnd`

```tsx
<AnchorList alignItemsAtEnd ... />
```

Прижимает контент к концу, пока его меньше экрана. В переписке первые сообщения
обязаны стоять внизу, а не висеть под навбаром.

Разницу добирает сдвиг слоя контейнеров вниз.

Сдвиг, а не отступ в раскладке: высота контента от него не меняется, поэтому
короткий список остаётся непрокручиваемым — прокручивать в нём нечего.

Место под панелью ввода из сдвига **вычитается**: его уже отдала распорка
[`insetEnd`](insets.md), и отдать дважды — значит опустить контент под панель и
сделать список прокручиваемым на пустом месте. Считается сдвиг на UI-потоке, в
такт клавиатуре: пока контента меньше экрана, именно он, а не скролл, поднимает
контент вместе с ней.

## `anchoredEndSpace`

Распорка у конца списка, растущая до якоря.

```tsx
<AnchorList
  anchoredEndSpace={{
    anchorIndex: quotedIndex,
    anchorOffset: 12,
    onSizeChanged: setSpaceSize,
  }}
/>
```

| Поле | Что делает |
| --- | --- |
| `anchorIndex` | Элемент, который должен доставать до верхней кромки |
| `anchorOffset` | Дополнительный отступ над якорем |
| `maxSize` | Верхняя граница размера распорки |
| `onSizeChanged` | Текущий размер; меняется вместе с раскладкой |

### Зачем

Переход к цитируемому сообщению у самого конца переписки. Под ним контента на
экран не хватает, скролл упирается в границу — и цитата встаёт не у кромки, а
где-то посередине.

Распорка резервирует место ровно настолько, чтобы якорный элемент мог подняться к
верхней кромке:

```
размер = max(0, высота вьюпорта − контент под якорем − anchorOffset)
```

и не больше `maxSize`, если он задан.

### Отношение к порогам

В отступ конца распорка входит, а в расстояние до кромки для порогов подгрузки —
**нет**: иначе подгрузка срабатывала бы на пустом месте, приняв распорку за
непрочитанный контент.

## `snapToIndices`

```tsx
<AnchorList snapToIndices={[0, 10, 20, 30]} />
```

Точки притяжения скролла. Индексы переводятся в смещения и уходят в
`snapToOffsets` нативного `ScrollView`.

Смещения считаются на рендере, поэтому до измерения соответствующих строк они
приблизительны. Для точного снапа задавайте размеры через `getFixedItemSize`.

## Что происходит одновременно

| Механика | Работает вместе с |
| --- | --- |
| `initialScroll` | Всем: пока она активна, пороги и компенсация не мешают доводке |
| `maintainScrollAtEnd` | `maintainVisibleContentPosition` — одна держит конец, другая видимую строку |
| `alignItemsAtEnd` | `maintainScrollAtEnd` — типовая пара для переписки |
| `anchoredEndSpace` | `scrollToKey` — распорка нужна ровно ради него |

## Проверить руками

Стенды «Стартовая позиция» и «Переход к сообщению» в [`example/`](../example).
Распорка `anchoredEndSpace` в примере не показана — её проще проверить на своих
данных: задайте `anchorIndex` последней строке и сравните переход к ней с
выключенной распоркой и с включённой.
