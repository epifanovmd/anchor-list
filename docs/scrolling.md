# Скролл и позиционирование

Где список открывается, как его двигать программно и как он сам держится у
конца.

## Стартовая позиция

```tsx
<AnchorList initialScroll={{ type: "end" }} ... />
```

```ts
type AnchorListInitialScroll =
  | { type: "end" }
  | { type: "offset"; offset: number }
  | { type: "index"; index: number; viewPosition?: number; viewOffset?: number }
  | { type: "key"; key: string; viewPosition?: number; viewOffset?: number };
```

| Вариант | Куда открывается |
| --- | --- |
| `{ type: "end" }` | Конец контента — вместе с подвалом и распорками, а не последний элемент |
| `{ type: "offset", offset }` | Прямое смещение в координатах контента |
| `{ type: "index", index, viewPosition, viewOffset }` | К элементу; `viewPosition` — куда прижать (0 к началу, 1 к концу, 0.5 по центру), `viewOffset` — поправка в px |
| `{ type: "key", key, viewPosition, viewOffset }` | К элементу по ключу — то же, что `index`, но адрес переживает подгрузку и перезагрузку данных |

Ключа может не оказаться в данных — строку удалили между снимком и открытием.
Тогда список открывается как без стартовой позиции, сразу, а не по страховке
первого показа; канал `initial` печатает `missing`. Пустые данные считаются ещё
не загруженными: список ждёт их, и если ключ придёт с первой страницей —
откроется на нём.

Стартовая позиция задаётся пропом, а не методом ref: список должен открыться
сразу на месте, без видимого переезда.

### До стартовой позиции список не показан

Пока строки не измерены, их размеры оценочные, и точная позиция цели
неизвестна. Список доводит скролл до цели за несколько кадров и показывается,
когда цель перестала уезжать и строки на экране измерены. Пользователь видит
сразу нужное место, а не переезд к нему. Если измерения не приходят вовсе, показ
завершает страховка по времени.

Чем точнее `estimatedItemSize` и чем больше строк объявлено через
`getFixedItemSize`, тем меньше попыток нужно. Что печатает доводка и как это
читать — [Симптомы](troubleshooting.md#список-мигает-или-дёргается-при-открытии).

Пока стартовая позиция активна, пороги подгрузки, удержание позиции и
прилипание к концу не вмешиваются.

### Восстановление позиции

Снимок снимает `ref.getScrollAnchor()` — ключ строки у начальной кромки и её
смещение от кромки, — а восстанавливает `initialScroll` типа `key`:

```tsx
// при уходе с экрана
storage.write(id, listRef.current?.getScrollAnchor());

// при открытии
const saved = storage.read(id);
<AnchorList
  initialScroll={saved && { type: "key", key: saved.key, viewOffset: saved.offset }}
/>;
```

Хранилище должно быть синхронным: MMKV, а не AsyncStorage, потому что позиция
нужна к первому кадру. Смещение храните как есть, без округления, иначе
позиция будет уползать на точку при каждом открытии. Снимок берётся по
последнему обработанному событию скролла, поэтому снимайте его, когда список
стоит: в `onScrollEndDrag` и по смене видимого диапазона.

Полный рецепт с кодом — [Рецепты](recipes.md#восстановление-позиции).

## Программный скролл

Четыре метода ref: `scrollToIndex`, `scrollToKey`, `scrollToOffset`,
`scrollToEnd`. Параметры — в [Императивном API](imperative-api.md#скролл).

Пока идёт программный скролл, пороги подгрузки не проверяются. `scrollToEnd`
доводит позицию повторно, если измерения последних строк сдвинули конец. Жест
пользователя отменяет доводку.

**Ключ надёжнее индекса.** После подгрузки сверху тот же элемент лежит на
другом индексе:

```tsx
// нет: индекс мог устареть между сохранением и переходом
listRef.current?.scrollToIndex({ index: savedIndex });

// да
const found = listRef.current?.scrollToKey({ key: savedKey });
if (!found) loadContextAround(savedKey);
```

## Прилипание к концу

Новое сообщение должно оказаться на экране само, но только если пользователь и
так стоял внизу. Если он читает историю, дёргать его нельзя.

```tsx
<AnchorList
  maintainScrollAtEnd={{ onlyWhenAtEnd: true, animated: true }}
  maintainScrollAtEndThreshold={0.1}
/>
```

| Поле | По умолчанию | Что делает |
| --- | --- | --- |
| `onlyWhenAtEnd` | `false` | Прилипать только если пользователь уже у конца |
| `animated` | `false` | Доводить позицию анимацией |

«У конца» — это в пределах `maintainScrollAtEndThreshold` от конца контента, по
умолчанию десятая часть экрана. Порог отдельный от порогов подгрузки.

Что важно:

- Признак «пользователь был у конца» снимается **до** того, как контент вырос.
  Иначе после вставки он всегда был бы ложным.
- Скролл откладывается на следующий кадр, чтобы новый контент успел разложиться
  и конец посчитался по фактическим размерам.
- Если за этот кадр пользователь начал жест или увёл список, прилипание
  отменяется.

Тот же порог отдаётся наружу сигналом `isWithinMaintainScrollAtEndThreshold` —
на нём строится кнопка «вниз», см. [Рецепты](recipes.md#кнопка-вниз).

## `alignItemsAtEnd`

```tsx
<AnchorList alignItemsAtEnd ... />
```

Пока контента меньше экрана, прижимает его к концу: три сообщения в новой
переписке лежат внизу у панели ввода, а не вверху под навбаром. Высота контента
при этом не меняется, короткий список остаётся непрокручиваемым.

Место под панелью ввода из сдвига вычитается — его уже отдала распорка
[`insetEnd`](insets.md). Сдвиг считается на UI-потоке, поэтому короткий список
едет вместе с клавиатурой.

## `anchoredEndSpace`

Распорка у конца списка, которая растёт до тех пор, пока заданный элемент не
сможет подняться к верхней кромке. Нужна для перехода к цитируемому сообщению у
самого конца переписки, где под целью не хватает контента на экран.

```tsx
<AnchorList
  anchoredEndSpace={{
    anchorIndex: quotedIndex,
    anchorOffset: 12,
    onSizeChanged: setSpaceSize,
  }}
/>
```

| Поле | Что делает |
| --- | --- |
| `anchorIndex` | Элемент, который должен доставать до верхней кромки |
| `anchorOffset` | Дополнительный отступ над якорем |
| `maxSize` | Верхняя граница размера распорки |
| `onSizeChanged` | Текущий размер; меняется вместе с раскладкой |

Размер распорки:

```
размер = max(0, высота вьюпорта − контент под якорем − anchorOffset)
```

и не больше `maxSize`, если он задан. В расстояние до кромки для порогов
подгрузки распорка не входит. Полный сценарий — [Рецепты](recipes.md#переход-к-цитате).

## `snapToIndices`

```tsx
<AnchorList snapToIndices={[0, 10, 20, 30]} />
```

Точки притяжения скролла. Индексы переводятся в смещения и уходят в
`snapToOffsets` нативного `ScrollView`. До измерения строк смещения
приблизительны — для точного снапа задавайте `getFixedItemSize`.

## Что работает одновременно

| Механика | Работает вместе с |
| --- | --- |
| `initialScroll` | Всем: пока она активна, пороги и компенсация не вмешиваются |
| `maintainScrollAtEnd` | `maintainVisibleContentPosition` |
| `alignItemsAtEnd` | `maintainScrollAtEnd`, `insetEnd` |
| `anchoredEndSpace` | `scrollToKey` |
