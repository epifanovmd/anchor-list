# Производительность

## Что настраивается

| Проп | По умолчанию | Влияет на |
| --- | --- | --- |
| `drawDistance` | `400` | Сколько строк смонтировано за пределами экрана |
| `scrollThrottleDistance` | `24` | Как часто пересчёт диапазона уходит в JS при скролле |
| `recycleItems` | `false` | Перемонтирование поддерева при смене элемента |
| `getItemType` | — | Точность переработки и оценки размеров |
| `getFixedItemSize` | — | Нужно ли измерять строку вообще |
| `estimatedItemSize` | — | Качество первых кадров |
| `itemsAreEqual` | по ссылке | Пропуск повторных рендеров ячейки |

## Порядок настройки

1. **`getItemType`** — влияет на переработку контейнеров и точность оценки.
2. **`recycleItems`** — даёт больше всего на однотипных строках. Состояние
   внутри ячеек при этом переводится на
   [`useAnchorListItemState`](rendering.md#состояние-внутри-ячейки).
3. **`getFixedItemSize`** там, где размеры известны — убирает измерение целиком.
4. **`estimatedItemSize`** — влияет на открытие.
5. **`drawDistance`** — последним и только по результатам замера.

## `drawDistance`

Запас отрисовки за пределами вьюпорта, px. Строки этого запаса смонтированы и
измерены заранее.

| Значение | Когда |
| --- | --- |
| Меньше 400 | Строки очень тяжёлые |
| 400 (по умолчанию) | Обычный случай |
| 600–800 | Строки лёгкие, скролл быстрый: списки сообщений, ленты картинок |

Больше 800 обычно бессмысленно: список сам растит запас по скорости.

### Рост по скорости

По ходу движения буфер растёт со скоростью, потолок — полтора экрана. Назад он не
растёт.

Выше примерно половины экрана в миллисекунду запас по скорости снимается совсем;
симметричный `drawDistance` при этом остаётся.

Настроек у этого нет.

## Что список делает сам

- **Слияние событий кадра** в один проход.
- **Шаг пересчёта** диапазона: 24 px.
- **Пакетирование измерений**: замеры копятся до конца кадра и применяются одним
  проходом.
- **Адресные сигналы**: скролл, сдвинувший одну строку, перерисовывает один
  контейнер.
- **Фиксация средних размеров** после 32 замеров на тип.
- **Отсечение шума измерений**: изменение высоты меньше порога раскладку не
  двигает.

## Встроенный замер

Отдельная от [диагностики](debugging.md) система: диагностика объясняет один
кадр, замер считает стоимость за окно. Величин «на событие» здесь нет — строки
собираются раз в секунду.

```tsx
import { anchorListPerf, useAnchorListPerf } from "@epifanovmd/anchor-list";

// Сессия на время жизни экрана.
useAnchorListPerf("chat");

// Или вручную.
anchorListPerf.start("chat");
anchorListPerf.stop();
```

Выключен по умолчанию: каждая точка замера в ядре — одна проверка флага.

```ts
anchorListPerf.help();     // все счётчики и величины с подписями
```

Отчёт можно забрать себе — например, чтобы показывать числа на экране:

```ts
anchorListPerf.setSink((report, text) => setLines(current => [text, ...current]));

// Накопленное за сессию на любой момент — окно закрывается раз в секунду.
const snapshot = anchorListPerf.getSnapshot();
```

Свои события считаются тем же счётчиком:

```tsx
const renderItem = useCallback(({ item }) => {
  anchorListPerf.count("renderItem");

  return <Row item={item} />;
}, []);
```


| Раздел | На что смотреть |
| --- | --- |
| `кадры` | `медиана` — как список идёт обычно; `p95` — где живёт рывок; `длинных` — кадры дольше 24 мс |
| `скролл` | `лаг` — отставание пересчёта от нативного скролла; `JS` — время в JS на событие |
| `диапазон` | `окно` — элементов в диапазоне; `контейнеров` — смонтировано; `без запаса` — проходов, на которых скорость сняла запас |
| `привязка` | `новых` растёт — контейнеров не хватает; `перепривязок` много — типы не помогают |
| `пустоты` | Должно быть «нет». Ненулевое — в кадре видны незакрытые полосы |
| `стики` | Цена прилипания на проходе |
| `измерения` | `пропущено` — замеры, отсечённые как шум |
| `раскладка` | `задержка` — сколько измерения ждали общего прохода |
| `рендеры` | `на 1000px` — вызовов `renderItem` на тысячу пикселей прокрутки |

Строка `mvcp` появляется, когда работает удержание позиции —
см. [Удержание позиции](maintain-position.md#что-видно-в-замере).

Разделы без событий за окно не печатаются. При остановке сессии печатается итог
за всё время.

### Как читать

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| `пустоты` ненулевые | Диапазон не успевает за скроллом | Увеличить `drawDistance`; проверить вес строк |
| `новых` растёт при скролле | Контейнеров не хватает | Уточнить `estimatedItemSize` и типы |
| `перепривязок` много | Контейнеры не попадают по типу | Пересмотреть `getItemType` |
| `на 1000px` большое | `renderItem` вызывается чаще, чем нужно | Включить `recycleItems`, задать `itemsAreEqual` |
| `лаг` десятки пикселей | JS не успевает за нативным скроллом | Смотреть, что тяжёлого в кадре помимо списка |
| `длинных` кадров много при спокойном скролле | Дело не в диапазоне | Профилировать содержимое строк |
| `медиана` в норме, `p95` втрое выше | Регулярные срывы | Смотреть `flush`, второй проход компенсации, тяжёлые замеры |
| `медиана` сама по себе высокая | Ровно медленно | Смотреть `диапазон` и `рендеры` |

## Чего замер не покажет

Он меряет список, а не строки: что именно тяжело в `renderItem`, видно только
профайлером.

## Проверить руками

Стенд «Нагрузка» в [`example/`](../example): тысяча сообщений, подгрузка в обе
стороны, прилипающие даты, измеряемые высоты, без настроек и экранных счётчиков.
