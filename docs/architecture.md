# Архитектура

Как список устроен внутри. Ничего из этого не экспортируется: внутренности
меняются вместе с реализацией.

## Общая схема

```
┌──────────────────────────────────────────────────────────┐
│  AnchorList (компонент)                                  │
│  тонкая оболочка: монтирует ScrollView, раздаёт контекст  │
└───────────┬──────────────────────────────┬───────────────┘
            │                              │
    ┌───────▼────────┐            ┌────────▼─────────┐
    │  ListRuntime   │  сигналы   │   ListStore      │
    │  расчёт вне    ├───────────►│  адресные        │
    │  React         │            │  подписки        │
    └───────┬────────┘            └────────┬─────────┘
            │                              │
   ┌────────▼─────────┐          ┌─────────▼──────────┐
   │  ListMetrics     │          │ ListItemContainer  │
   │  ключи, размеры, │          │ по одному на       │
   │  позиции         │          │ видимую строку     │
   └──────────────────┘          └────────────────────┘
```

Диапазон отрисовки, позиции и привязка контейнеров считаются вне React. В дерево
уходят адресные сигналы: скролл и измерения перерисовывают только затронутый
контейнер.

## Слои

### Компонент

`AnchorList` монтирует `Animated.ScrollView`, отдаёт ядру размеры и события и
раздаёт дереву контекст. Логики раскладки в нём нет.

Внутри `ScrollView` сверху вниз:

| Узел | Зачем |
| --- | --- |
| Якорь компенсации | Первый ребёнок контента, нулевой размер — за ним следит нативное удержание позиции |
| Шапка | `ListHeaderComponent`, измеряется |
| Слой контейнеров | Задаёт высоту контента; контейнеры внутри позиционированы абсолютно. Короткий контент прижимает к концу трансформ слоя — в высоту он не входит |
| Распорка у конца | `anchoredEndSpace` |
| Подвал | `ListFooterComponent`, измеряется |
| Распорка нижнего отступа | Высота `insetEnd`; ниже подвала |

Снаружи `ScrollView`, но внутри обёртки — слой прилипших копий: он живёт в
координатах вьюпорта.

### Расчётное ядро

`ListRuntime` — координатор: держит смещение, размер вьюпорта и текущий диапазон,
содержательную работу делают отдельные модули. Здесь же задан порядок вызовов:

- смена пропов снимает якорь компенсации **до** смены данных и восстанавливает
  позицию **после**;
- приём измерения копит изменения до конца кадра, но якорь снимает сразу;
- восстановление позиции считает раскладку дважды в одном синхронном проходе с
  записью позиций;
- обработка скролла отбрасывает события, отправленные до применения сдвига,
  считает проход по живому смещению UI-потока и сливает события кадра в один
  проход.

### Хранилище сигналов

`ListStore` — именованные значения с адресной подпиской. Значения читаются
синхронно из расчётного цикла и подписываются точечно из компонентов; запись без
изменения значения подписчиков не будит.

Сигналы двух видов:

- **общие** — состояние всего списка (`totalSize`, `isNearEnd`,
  `firstVisibleIndex`, …); они выходят наружу через `sharedValues` и `state`;
- **адресные, по одному набору на контейнер** — `containerPosition3`,
  `containerItemKey3`, `containerSticky3` и так далее.

### Метрики

`ListMetrics` — размеры и позиции:

| Часть | За что отвечает |
| --- | --- |
| Соответствие ключ ↔ индекс | Обратное преобразование за константу |
| Размеры элементов | Объявленные, измеренные, оценочные; пометка «ещё не измерен» |
| Средние по типам | Оценка неизмеренных строк; фиксируется после 32 замеров |
| Префиксные суммы позиций | Позиция элемента без обхода всего списка |

Всё адресуется ключом, а не индексом.

## Контейнеры

Контейнер — единица монтирования. Смонтированы только те, что попадают в
диапазон отрисовки.

```
данные:      [0][1][2] ... [847][848][849][850] ... [9999]
                            └──── диапазон ────┘
контейнеры:                  #3   #7   #1   #4
```

Контейнер переживает смену элемента: ядро меняет его сигналы, перерисовывается
только он.

### Пул

`ContainerPool` раздаёт контейнеры под запрошенные строки. Свободный контейнер
того же типа предпочтительнее: React меняет пропы вместо перемонтирования.

Прилипающие контейнеры живут отдельно: они остаются смонтированными за пределами
видимого диапазона и под обычные элементы не уходят. Между прилипающей и обычной
ролью контейнеры не переиспользуются.

Контейнер без привязки не размонтируется — его уводят туда, куда скролл не
доходит.

## Проход раскладки

При скролле:

```
событие скролла (UI-поток, worklet)
  └─ запись scrollOffset
  └─ шагами по 24px → JS
       └─ ListRuntime.setScroll
            ├─ слияние событий кадра в один проход
            ├─ расчёт скорости
            ├─ computeVisibleRange       — какие строки нужны
            ├─ collectContainerRequests  — какие из них не отрисованы
            ├─ ContainerPool.allocate    — раздача контейнеров
            ├─ запись позиций в сигналы  — перерисуются только сдвинувшиеся
            ├─ EdgeThresholds.check      — пороги подгрузки
            ├─ StickyPublisher           — активные якоря
            └─ ViewabilityTracker        — если есть подписчики
```

При измерении ячейки:

```
onLayout ячейки
  └─ фильтр шума (субпиксельная разница игнорируется)
  └─ ListRuntime.setItemSize
       ├─ якорь компенсации снимается сразу
       └─ LayoutScheduler — копит до конца кадра
            └─ один проход раскладки на всю пачку
                 └─ восстановление позиции по якорю
```

## Компенсация позиции

Сдвиг выполняет нативный `ScrollView`, а не JS.

Ему передан `maintainVisibleContentPosition={{ minIndexForVisible: 0 }}`, а
первым ребёнком контента лежит распорка нулевого размера. Нативный код
запоминает её кадр перед mount-транзакцией и после неё добавляет смещение кадра
к `contentOffset`.

Позиции контейнеров, высота слоя и сдвиг распорки публикуются одной транзакцией
`ListStore`. Отложенный scroll-pass в этом же кадре уступает layout-pass с
замерами.

Позиция распорки **накопительная**: нативный слой смотрит на смещение её кадра
между транзакциями. Сама распорка вынесена далеко за пределы контента, чтобы
попадать под `minIndexForVisible` при любом смещении.

## Прилипание

Смещение якоря и предикат «стоит у кромки» — worklet-функции, считаются на
UI-потоке.

Предел смещения считается в JS для каждого якоря и зависит только от геометрии
соседей, не от позиции скролла.

Три состояния и слой копий — в [Прилипание](sticky.md#слой-прилипших-копий).

## Структура исходников

```
src/
  index.ts            публичный экспорт
  types.ts            публичные типы

  components/         React-слой
    AnchorList.tsx      компонент
    ListContainers      слой контейнеров
    ListItemContainer   один контейнер
    ListItemContent     содержимое ячейки и её измерение
    ListStickyFrame     обёртка прилипающей строки
    ListStickyOverlay   слой прилипших копий
    ListStickyPin       копия одной кромки
    ListScrollAdjust    якорь компенсации
    ListAnchoredEndSpace распорка у конца
    ListInsetEndSpace   распорка нижнего отступа

  core/               расчёт вне React
    runtime/            координатор и приведение пропов
    layout/             диапазон, привязка контейнеров, распорки, пакетирование
    scroll/             стартовая позиция, программный скролл, нижний отступ, скорость
    mvcp/               удержание видимой позиции
    sticky/             якоря, пределы, смещения
    edges/              пороги кромок
    viewability/        видимость элементов
    data/               разбор данных в ключи и типы

  model/              состояние
    list-store          хранилище сигналов
    list-signals        имена и начальные значения
    list-state          доступ снаружи дерева
    list-context        контекст дерева
    container-pool      пул контейнеров
    metrics/            ключи, размеры, позиции, средние

  hooks/              мосты в React и Reanimated
  perf/               замер производительности
```
