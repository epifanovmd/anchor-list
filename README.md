**Виртуализированный список для React Native, который держит на месте не экран, а
строку.**

Подгрузилась история сверху, картинка раздула ячейку за кадром, выехала
клавиатура — то, на что смотрит пользователь, остаётся ровно там, где было.

```sh
yarn add @epifanovmd/anchor-list
```

---

## 🤔 Почему AnchorList

### 📌 Точка отсчёта — строка, а не смещение

Обычный список сохраняет `contentOffset`. Но пользователь смотрит не на
смещение, а на конкретное сообщение, и любое изменение выше кадра уводит это
сообщение вниз. `AnchorList` снимает якорь **до** изменения и восстанавливает
позицию **после** — в той же транзакции, в которой переставляются контейнеры.
Промежуточного кадра не возникает, а жест и инерция не обрываются.

- Подгрузка страницы истории — видимая строка не двигается;
- ячейка выше кадра изменила высоту — сдвиг компенсируется в том же кадре;
- компенсация включается раздельно: по вставке данных и по изменению размеров.

### 🎯 Механики, которых у списков обычно нет

Не надстройки поверх, а то, из чего список собран:

- **прилипание на обеих кромках сразу** — заголовки дат сверху, аватары групп
  снизу, независимыми наборами;
- **распорки под панель ввода и клавиатуру** — контент, индикатор скролла и
  прилипшие якоря едут вместе с ней, покадрово;
- **резерв места у конца**, чтобы переход к цитате поставил её у кромки, а не
  упёрся в границу контента;
- **стартовая позиция**, до которой список просто не показан: кадра, посчитанного
  по оценкам, пользователь не увидит.

### ⚡ Расчёт живёт вне React

Диапазон отрисовки, позиции и привязка контейнеров считаются в отдельном ядре, а
в дерево уходят адресные сигналы. Скролл, сдвинувший одну строку, перерисовывает
**один контейнер**, а не список. Сам компонент — тонкая оболочка над
`ScrollView`.

Сверх этого: переработка контейнеров по типам строк, объявленные размеры вместо
измерения, слияние событий кадра и буфер отрисовки, растущий со скоростью броска
и снимающийся там, где он перестаёт окупаться.

### 🧵 Состояние прямо на UI-потоке

24 значения через shared values: смещение, фазы жеста, скорость, расстояния до
кромок, размеры, видимый диапазон, активные якоря прилипания. Тень под навбаром,
свой скроллбар и кнопка «вниз» анимируются покадрово **без единого рендера**.

Те же значения доступны и в React — с адресной подпиской: перерисовывается
только тот, чьё значение изменилось. Читать можно снаружи списка и до того, как
он смонтируется.

### 🛠 Удобно с первой строки

- **четыре обязательных пропа** — остальное включается по одному;
- **нативного кода нет** — линковка не нужна, Expo Go работает;
- **типы на всё**, включая сигналы состояния и конфиги прилипания;
- **восемь каналов диагностики** — по одному на механику, с подписью каждой
  величины: что она показывает и о чём говорит;
- **встроенный замер** — счётчики, медиана и p95 кадров пачкой раз в секунду.

### 🔍 Честные границы

Список вертикальный и одноколоночный — я так сделал специально. Всё
перечисленное выше опирается на одну ось и один столбец. Чего в нём нет и
почему — отдельным разделом: [Ограничения](docs/limitations.md).

## ✨ Возможности

**Позиция и прокрутка**

- [x] Удержание видимой позиции при вставке и удалении элементов
- [x] Удержание при изменении размеров уже отрисованных строк
- [x] Свой выбор якоря восстановления (`shouldRestorePosition`)
- [x] Стартовая позиция по индексу, ключу, смещению или концу списка
- [x] Прилипание к концу при добавлении контента — с отменой, если пользователь
      увёл список
- [x] `scrollToIndex`, `scrollToKey`, `scrollToOffset`, `scrollToEnd` с
      `viewPosition` и `viewOffset`
- [x] Снап по индексам (`snapToIndices`)
- [x] Прижатие короткого контента к концу (`alignItemsAtEnd`)
- [x] Резерв места у конца под якорь (`anchoredEndSpace`)

**Прилипание**

- [x] Обе кромки одновременно, независимыми наборами индексов
- [x] Два режима: прилипает вся строка или только объект внутри неё
- [x] Слой копий поверх списка — у стоящего якоря нет покадрового трансформа
- [x] Границы групп: якорь не поднимается выше своей группы
- [x] Динамический отступ кромки shared value — навбар, панель ввода, клавиатура

**Клавиатура и отступы**

- [x] `insetEnd` одним shared value: распорка, подъём смещения и инсеты
      индикатора скролла считаются от него сами
- [x] Интерактивное закрытие клавиатуры свайпом — контент едет за ней без рывка

**Подгрузка**

- [x] Пороги в долях вьюпорта в обе стороны
- [x] Однократность на жест и гистерезис у границы
- [x] Общий замок: две кромки не выстрелят на одном жесте
- [x] Повторное срабатывание, когда контент вырос, а до кромки по-прежнему близко

**Виртуализация**

- [x] Переработка контейнеров по типам строк (`recycleItems`, `getItemType`)
- [x] Объявленные размеры без измерения вовсе (`getFixedItemSize`)
- [x] Буфер отрисовки, растущий со скоростью броска
- [x] Слияние событий кадра и адресные сигналы вместо перерисовки списка
- [x] Своё сравнение элементов (`itemsAreEqual`)

**Состояние наружу**

- [x] 24 сигнала на UI-поток через `sharedValues`
- [x] Те же значения в React с адресной подпиской
- [x] Состояние ячейки, переживающее переработку контейнера
- [x] Видимость: несколько независимых наборов порогов и `minimumViewTime`
- [x] Императивный ref: позиции, размеры, видимый диапазон, смещение, скорость

**Слоты и инструменты**

- [x] `ListHeaderComponent`, `ListFooterComponent`, `ListEmptyComponent`,
      `ItemSeparatorComponent`
- [x] Диагностика: восемь каналов по числу механик
- [x] Замер производительности с отчётом раз в секунду
- [x] TypeScript

## 📦 Установка

```sh
yarn add @epifanovmd/anchor-list
```

Нужны `react-native-reanimated` 4+ и `react-native-worklets`. Нативного кода в
пакете нет — линковка не нужна, Expo Go работает. Настройка babel и проверка
сборки — в [руководстве по установке](docs/installation.md).

## 💻 Использование

```tsx
import { AnchorList } from "@epifanovmd/anchor-list";

<AnchorList
  data={messages}
  renderItem={({ item }) => <Message message={item} />}
  keyExtractor={message => message.id}
  estimatedItemSize={92}
/>;
```

Четыре пропа — и список работает. Дальше механики включаются по одной:

```tsx
<AnchorList
  data={messages}
  renderItem={renderItem}
  keyExtractor={keyExtractor}
  estimatedItemSize={92}
  // Видимая строка не двигается при подгрузке истории и росте ячеек
  maintainVisibleContentPosition={{ data: true, size: true }}
  // Заголовки дат прилипают к верхней кромке
  sticky={sticky}
  // Клавиатура и панель ввода — контент едет вместе с ними
  insetEnd={insetEnd}
  // Новое сообщение оказывается на экране само
  maintainScrollAtEnd={{ onlyWhenAtEnd: true }}
  onStartReached={loadOlder}
/>;
```

Состояние — покадрово на UI-потоке, без рендеров:

```tsx
const scrollOffset = useSharedValue(0);
const sharedValues = useMemo(() => ({ scrollOffset }), [scrollOffset]);

const shadow = useAnimatedStyle(() => ({
  opacity: Math.min(1, scrollOffset.value / 24),
}));

<AnchorList sharedValues={sharedValues} ... />;
```

Целые экраны — переписка, бесконечная лента, восстановление позиции — собраны
в [Рецептах](docs/recipes.md). С чего начать — [Быстрый
старт](docs/quick-start.md).

## 🔬 Диагностика и замер

Когда что-то ведёт себя не так, гадать не нужно: у каждой механики свой канал, а
у каждой величины в логе — подпись, что она показывает.

```ts
import { anchorListDebug, setAnchorListDebug } from "@epifanovmd/anchor-list";

anchorListDebug.help();       // какие каналы бывают и что в них
setAnchorListDebug("mvcp");   // включить одну механику
```

```
[mvcp·shift]        2.416 42    reason=данные moved=+18 applied=+18 lost=0
[mvcp·miss]!        2.418 42    before=120 after=138 error=18
```

Рядом — замер: кадры с медианой и p95, стоимость проходов, переработка
контейнеров, незакрытые полосы. Подробно:
[Диагностика](docs/debugging.md) и [Производительность](docs/performance.md).

Сроков не назову, но сделать хочу:

> удержание позиции опирается на нативный `maintainVisibleContentPosition`,
> которого нет в `react-native-web`. Подробности —
> в [Ограничениях](docs/limitations.md#web-требует-доработок).
